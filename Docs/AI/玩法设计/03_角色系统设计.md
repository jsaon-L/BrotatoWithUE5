# 03 · 角色系统设计

> 对应源码：`items/characters/<name>/<name>_data.tres`、`items/characters/character_data.gd`、`items/global/item_parent_data.gd`、`effects/items/*.gd`
> 本版本共 **44 个可玩角色**（目录内 45 个 tres，`ItemService.characters` 注册 44 个）。

---

## 1. 设计定位

角色在 Brotato 中**不是"皮肤 + 小加成"，而是"规则模组"**。它通过三种手段改变一局游戏：

| 手段 | 强度 | 例子 |
|---|---|---|
| **属性偏置**（加减主属性） | 弱 | Well Rounded：HP+5 / 速度+5 / 收获+8 |
| **获取倍率**（`gain_*`） | 中 | Ranger：`gain_ranged_damage +50%`、`gain_max_hp −25%` |
| **规则覆写**（`REPLACE` / 开关） | **强** | Bull：`weapon_slot = 0`（无武器）；Demon：`hp_shop = 1`（用血买东西）；Multitasker：`weapon_slot = 12` |

**设计原则**：几乎每个角色都是"**强正向 + 强负向**"的成对配置，制造明确的 Build 方向与明确的短板。没有纯上位角色。

## 2. 数据结构

`items/characters/character_data.gd`（`CharacterData extends ItemData extends ItemParentData`）

```gdscript
# ItemParentData
my_id : String                  # "character_well_rounded"
unlocked_by_default : bool
icon : Resource
name : String                   # 本地化键 "CHARACTER_WELL_ROUNDED"
tier : Tier                     # 用于 UI 边框着色（运行时会被改写为已通关危险度）
value : int
effects : Array[Effect]         # ★ 核心：全部角色特性
tracking_text : String
# ItemData
max_nb : int
item_appearances : Array
tags : Array[String]
# CharacterData
wanted_tags : Array[String]     # 商店 5% 概率只出带这些 tag 的物品
starting_weapons : Array[WeaponData]   # 可选初始武器池；为空则用全局 9 把默认池
```

### 2.1 Effect 的三种存储语义（`items/global/effect.gd`）

| StorageMethod | 行为 | 用途 |
|---|---|---|
| `SUM` (0) | `effects[key] += value` | 普通属性加减 |
| `KEY_VALUE` (1) | `effects[custom_key].push_back([key, value])` | 复杂元组效果 |
| `REPLACE` (2) | 备份原值后**整体覆写** | 上限/槽位类（`dodge_cap`、`weapon_slot`） |

> `custom_key != ""` 会**强制走数组分支**，即使 `storage_method == SUM`。

### 2.2 角色常用的特殊 Effect 类型

| Effect 类 | 语义 |
|---|---|
| `ClassBonusEffect` | `weapon_class_bonus.push_back([set_id, stat, value])` — 对某职业武器直接加值（`lifesteal` 除以 100） |
| `StatGainsModificationEffect` | `for stat in stats_modified: effects["gain_"+stat] += value` |
| `GainStatForEveryStatEffect` | `stat_links.push_back([key, value, stat_scaled, nb, perm_only])` |
| `ConvertStatEffect` | 每 `value` 点源属性 → `to_value` 点目标属性，转换比例 `pct_converted%` |
| `StatWithMaxEffect` | 带 `max_value` 上限的临时属性 |
| `ChanceStatDamageEffect` | `[属性名, 百分比, 触发概率]`，按属性值造成伤害 |
| `StatCapEffect` | 覆写 `hp_cap` / `speed_cap`（**不用于 `dodge_cap`**，原因见 §8.3） |

### 7.3 解锁依赖图

```
初始 5 角色（Well Rounded / Brawler / Crazy / Ranger / Mage）
        │
        ├─ 通关任一角色 ──► 解锁 1 件装备 ──► 物品池变大 ──► 更易达成条件挑战
        │
        ├─ 达成条件挑战 ──► 解锁新角色 ──► 又产出新装备（循环）
        │
        └─ 在 Danger N 通关 ──► 解锁 1 个角色 + **全局** max_selectable_difficulty = N+1
                                （危险度在所有角色间共享，不需每个角色重刷）
```

- `chal_gatherer_1..5`：累计收集材料 300 / 2000 / 5000 / 10000 / 20000 → Lucky / Generalist / Multitasker / Pacifist / Saver
- `chal_lumberjack`：累计砍树 50 → Explorer

### 8.3 易错点

| 点 | 说明 |
|---|---|
| REPLACE 语义 | 必须备份 `base_value`，`unapply` 时还原 |
| ★ `StatCapEffect` 的卸载 | 它的 `unapply` 是**硬复位 999999** 而非还原 `base_value`（原作如此，需照抄）。**因此它只能用于 `hp_cap` / `speed_cap`（默认值本就是 999999）**。`dodge_cap`（默认 60）若走 `StatCapEffect`，卸下后会变成 999999 = 闪避上限失效。<br>→ **结论：Ghost 的 `dodge_cap=90` 与 Cryptid 的 `dodge_cap=70` 走普通 Effect 的 `REPLACE`（备份/还原 base_value），不是 `StatCapEffect`。** `[需回源确认：检查 ghost_effect_*.tres / cryptid_effect_*.tres 的 script 路径]` |
| 顺序依赖 | 角色效果必须在**武器/物品之前**应用（`weapon_slot` 等会影响后续判定） |
| Bull 分支 | `weapon_slot == 0` 时**跳过武器选择场景**，直接进难度选择 |
| `gain_*` 的 −100% | Mage / Pacifist 会让某属性归零，注意 `1 + (-100)/100 = 0` 的乘法结果，不要写成 clamp 到正数 |
| Renegade 的 −400% DMG% | `1 + (-400)/100 = -3`，会出现**负伤害**；原作靠 `max(1, ...)` 兜底到 1，必须保留 |
| 角色 tier 字段 | 运行时会被 UI 改写成"已通关最高危险度"用于边框着色，不要当成真 tier 用 |
