> 对应源码：`singletons/run_data.gd`、`singletons/utils.gd`、`singletons/temp_stats.gd`、`singletons/linked_stats.gd`、`singletons/weapon_service.gd`、`entities/units/unit/unit.gd`、`entities/units/player/player.gd`、`entities/units/player/player_stats.tres`

## 1. 属性存储三层架构

### 1.1 架构总览

| 层 | 载体 | 生命周期 | 典型来源 |
|---|---|---|---|
| **永久层** | `RunData.effects: Dictionary` | 整局 | 角色、物品、升级、武器套装、难度 |
| **临时层** | `TempStats`（波内） | 每波结束 `reset()` | 移动/静止状态、受击叠加、闪避叠加、5 秒周期叠加 |
| **联动层** | `LinkedStats`（继承 TempStats） | 每次装备/金币变化时全量重算 | "每 N 点 X 获得 Y" 类效果 |

### 1.2 取值公式（`utils.gd:172` + `run_data.gd:631-640`）

```
Utils.get_stat(name) = RunData.get_stat(name) + TempStats.get_stat(name) + LinkedStats.get_stat(name)

其中每层：  layer.get_stat(name) = layer_value[name] × (1 + effects["gain_" + name] / 100)
```

$$\text{FinalStat}(s) = \Big(E[s] + T[s] + L[s]\Big)\cdot\Big(1 + \frac{E[\text{gain\_}s]}{100}\Big)$$

> **重要**：`gain_*` 乘区**只有一份**（存在永久层 `effects` 里），但**三层各自独立乘**。数学上等价于上式，但实现时必须保证三层都乘，否则临时/联动加成会漏掉倍率。

**`gain_*` 的来源**：`StatGainsModificationEffect`（`effects/items/stat_gains_modification_effect.gd`）
```gdscript
for stat in stats_modified: effects["gain_" + stat] += value
```
例：Ranger 的 `gain_stat_ranged_damage = +50`，Cyborg 的 `gain_stat_ranged_damage = +250`。

### 1.3 LinkedStats 重算规则（`linked_stats.gd`）

数据结构：`effects["stat_links"]` 的每项 = `[目标属性, 每份数值, 缩放源, 每份需要的量, 是否只看永久层]`

```
amount = value × floor(scaled_amount / nb_stat_scaled)      ← 整数除法！
```

**缩放源（`stat_scaled`）支持的特殊键**：

| 键 | 取值 |
|---|---|
| `materials` | `RunData.gold`（并置 `update_on_gold_chance=true`，金币变化即重算） |
| `structure` | `effects["structures"].size()` |
| `living_enemy` | `RunData.current_living_enemies` |
| `living_tree` | `RunData.current_living_trees` |
| `common_item` | 不同 Tier I 物品种数 |
| `legendary_item` | 不同 Tier IV 物品种数 |
| `item_xxx` | 该物品持有数 |
| 其他 | 视为属性名；`perm_only=true` 只取 `RunData`，否则 `RunData + TempStats` |

**重算触发点**：`add_item` / `remove_item` / `add_weapon` / `add_gold`（仅当含 materials 链） / 升级选择完成后。

> **UE5 实现警告**：这是 O(N) 全量重算，触发频繁（捡钱时一个 Tick 内可能多次）。必须做**脏标记 + Tick 末统一重算**（模拟阶段 S11），原作靠 `_are_stats_dirty` 做批量 `stats_updated` 信号。

## 4. 各属性精确作用公式

### 4.1 最大生命（`player.gd:256`）

```gdscript
max_stats.health = clamp(Utils.get_stat("stat_max_hp"), 1, RunData.effects["hp_cap"]) as int
```
- 下限 **1**，上限 `hp_cap`（默认 999999，`StatCapEffect` 可覆写）
- 波开始时当前血量：`current_health = max(1, max_health × hp_start_wave / 100)`（`main.gd:975`）
- **每次升级永久 +1 max_hp，且立即回 1 血**（`main.gd:645,649`）

### 4.2 移动速度（`player.gd:257`）

```gdscript
max_stats.speed = 450 × (1 + min(Utils.get_stat("stat_speed"), speed_cap) / 100.0)
```
- 基础 **450 px/s**（`entities/units/player/player_stats.tres:9`）
- **1 点 speed = +1% = +4.5 px/s**

实际速度合成（`unit.gd:166`）：
```gdscript
move_input = _current_movement.normalized() × max(0, current_speed + bonus_speed + decaying_bonus_speed + _speed_rand_value)
velocity   = move_input - knockback_value
```
玩家 `speed_randomization = 0` → `_speed_rand_value = 0`。

| stat_speed | 实际速度 |
|---|---|
| 0 | 450 px/s |
| +10 | 495 |
| +30 | 585 |
| +50 | 675 |
| +100 | 900 |
| −20 | 360 |

**关键手感**：**无加速度、无摩擦、无惯性**。输入方向归一化后直接乘速度，松手瞬停。
★ **UE 实现**：`UFloatingPawnMovement`（`Acceleration` / `Deceleration` 取极大值以近似瞬时响应）或自定义 `UPawnMovementComponent`；
位移与滑墙走 `SafeMoveUpdatedComponent` + `SlideAlongSurface`（对齐原作两段 `test_motion`，margin 0.08）。

### 4.3 护甲（★ 双公式陷阱）

#### 玩家侧 —— 乘法减伤（`run_data.gd:687-697` + `player.gd:211`）

$$C_{armor}(A) = \begin{cases}\dfrac{10}{10 + |A|/1.5} & A \ge 0\\[8pt] 2 - \dfrac{10}{10+|A|/1.5} & A < 0\end{cases}$$

```gdscript
func get_dmg_value(dmg_value, armor_applied=true, _is_crit=false) -> int:
    var armor_coef = RunData.get_armor_coef(current_stats.armor)
    return max(1, round(dmg_value * armor_coef)) as int if armor_applied else dmg_value
```

| armor | 受伤系数 | 减伤率 |
|---|---|---|
| 0 | 1.000 | 0% |
| 3 | 0.833 | 16.7% |
| 5 | 0.750 | 25% |
| 10 | 0.600 | 40% |
| 15 | 0.500 | 50% |
| 20 | 0.4286 | 57.1% |
| 30 | 0.3333 | 66.7% |
| 50 | 0.2308 | 76.9% |
| 60 | 0.200 | 80% |
| 100 | 0.1304 | 87.0% |
| −10 | 1.400 | **+40% 受伤** |
| −20 | 1.5714 | +57% 受伤 |

**无硬上限，渐近 0，天然软上限（边际递减）。最低伤害恒为 1。**

#### 敌人侧 —— 固定减法（`unit.gd:313`）

```gdscript
func get_dmg_value(dmg_value, armor_applied=true, _is_crit=false) -> int:
    return max(1, dmg_value - current_stats.armor) as int if armor_applied else dmg_value
```
> Zone 1 所有敌人 `armor = 0`、`armor_increase_each_wave = 0`，但框架必须实现。

### 4.4 闪避（`player.gd:259` + `unit.gd:230`）

```gdscript
max_stats.dodge = min(dodge_cap / 100.0, Utils.get_stat("stat_dodge") / 100.0)
# 判定
if dodgeable and randf() < min(current_stats.dodge, dodge_cap / 100.0):
    full_dmg_value = 0; is_dodge = true
```
- **双重 clamp**（属性侧 + 判定侧）
- `dodge_cap` 默认 **60**；Ghost 覆写为 **90**，Cryptid 覆写为 **70**（`StorageMethod = REPLACE`）
- **没有"必中/保底"机制**：`is_miss` 变量恒为 false，`accuracy` 只影响散布角度，不产生 miss
- 闪避成功仍触发 `dmg_on_dodge` / `heal_on_dodge` / `temp_stats_on_dodge`
- **闪避成功也会进入无敌窗口**（只要 `dodgeable=true`）
- 闪避 / 免伤时**不播放闪白**

> **随机数比较符差异**：闪避用 `randf() <` ；暴击用 `Utils.get_chance_success()` 内部是 `randf() <=`（且 `chance==0` 直接返回 false）。`randf()` 取值 `[0,1)`。必须严格对齐。

### 4.5 生命回复（`run_data.gd:700-711`）

$$T_{regen}(R) = \frac{5.0}{1 + \dfrac{|R-1|}{2.25}}\ \text{秒/次}\qquad (R \le 0 \Rightarrow 99\ \text{s})$$

每次恢复 **1 HP**（`double_hp_regen` 时 2 HP）。

| hp_regen | 周期(s) | 每秒回复 |
|---|---|---|
| 1 | 5.000 | 0.20 |
| 2 | 3.462 | 0.29 |
| 3 | 2.647 | 0.38 |
| 5 | 1.800 | 0.56 |
| 10 | 1.000 | 1.00 |
| 15 | 0.692 | 1.44 |
| 20 | 0.529 | 1.89 |
| 30 | 0.360 | 2.78 |
| 50 | 0.220 | 4.56 |

> 全表由 `5.0 / (1 + |R-1|/2.25)` 逐项复算，可直接作为单测期望值。

特殊：
- `torture > 0`（item_torture）→ 计时器强制 **1.0 s**，每次回 `torture` 点（值 4）
- `double_hp_regen_below_half_health`（item_potion）→ 血量 <50% 时回复量翻倍
- 回复量会乘 `loop_count`（一次 tick 内补齐多个周期）
  ★ **UE 实现**：用 **Periodic GE**（`Spec->Period = T`），GAS 原生会在长帧时补齐多个 period，语义天然一致（§00 §3.3）

### 4.6 吸血（★ 与伤害无关）

| 炮塔 | **不吃** lifesteal |

### 4.7 收获（Harvesting）

**波末结算**（`main.gd:926-947`）：
$$\text{Harvest} = \text{stat\_harvesting} + \text{round}\Big(N_{enemies}\cdot\tfrac{\text{pacifist}}{100}\Big)\big[\div 2 \text{ 兽潮波}\big] + N_{trees}\cdot\text{cryptid} + \text{elite\_bonus}$$

结算后 **同时 `add_gold(val)` 和 `add_xp(val)`**。

**自增长**（`main.gd:1054-1074`，HarvestingTimer 0.66 s 后触发）：
$$\Delta H = \begin{cases} +\lceil H\cdot \tfrac{\text{harvesting\_growth}}{100}\rceil = +\lceil 0.05H\rceil & W \le 20\\[4pt] -\lceil 0.20H\rceil & W > 20\ \text{(无尽)}\end{cases}$$

`ENDLESS_HARVESTING_DECREASE = 20`（`run_data.gd:14`）。Farmer 的 `harvesting_growth` = 5+3 = **8**。

### 4.8 工程（Engineering）

不直接作用于玩家，只作为**武器/建筑的 `scaling_stats` 系数源**。

| 建筑 | 基础伤害 | 系数 |
|---|---|---|
| 标准炮塔 | 10 | `engineering × 0.8` |
| 激光炮塔 | 20 | `× 1.25` |
| 火箭炮塔 | 25 | `× 1.5` |
| 治疗炮塔 | 3 | `× 0.05` |

### 4.9 射程（`weapon_service.gd:13,22`）


### 4.10 攻击速度（`weapon_service.gd:86-102`）

```gdscript
# 原作（帧）
atk_spd = (Utils.get_stat("stat_attack_speed") + base_stats.attack_speed_mod) / 100.0
if atk_spd > 0:
    cooldown        = max(2, base_stats.cooldown * (1 / (1 + atk_spd))) as int
    recoil          = base_stats.recoil / (1 + atk_spd)

```

★ **UE 侧（秒，等价）**：

```cpp
else
    CooldownSeconds = FMath::Max(1.f/30.f, Base.CooldownSeconds * (1.f + FMath::Abs(AtkSpd)));
// ★ 不取整（旧版 "as int / 截断向零" 条目已作废，见 §00 §6）
```

- 原作单位 = 物理帧（60 fps），硬下限 2 帧 → **UE 侧单位 = 秒，硬下限 `1/30 s`**（数值等价）
- `attack_speed_mod` 是武器/套装/职业给的独立通道，与玩家 `stat_attack_speed` **相加后**一起参与

### 4.11 幸运（Luck）

只影响两处：

**A. 稀有度抽取**（`item_service.gd:326-349`）
$$f(L)=\begin{cases}1+L & L\ge 0\\ \dfrac{1}{1+|L|} & L<0\end{cases}\qquad L = \frac{\text{stat\_luck}}{100}$$
只放大「波次增量项」，不影响 BASE，且受 MAX_CHANCE 硬封顶。

**B. 消耗品掉落**（`main.gd:497`）
$$P_{consumable} = \min\big(1.0,\ \text{base\_drop\_chance}\times(1+L)\big)$$
注意此处 `L<0` 是**线性** `(1+L)`，与 A 的 `/(1+|L|)` **不同**。

### 4.12 暴击

```gdscript
# weapon_service.gd:124
crit_damage = base_stats.crit_damage              # 只来自武器，玩家无 crit_damage 属性
crit_chance = base_stats.crit_chance + Utils.get_stat("stat_crit_chance") / 100.0
```
武器默认：`crit_chance = 0.03`、`crit_damage = 1.5`（`weapon_stats.gd:7-8`）。

> `stat_crit_damage` 这个键**不存在**于 `init_stats()`，对应升级资源虽存在但未注册（废弃内容）。

## 5. 伤害结算总公式

### 5.1 玩家武器伤害构建（开波/属性变动时重算）

`weapon_service.gd:46-146` `init_base_stats()`，**严格按此顺序**：

```
1) base = weapon_stats.duplicate()

2) 应用 effects["weapon_bonus"]        （匹配 weapon_id）
       base[stat] += value

3) 应用 effects["weapon_class_bonus"]  （匹配武器所属 set）
       base[stat] += (value/100 if stat == "lifesteal" else value)

4) 处理武器自带 Effect
   · BurningEffect      → base.burning_data = 覆写
   · WeaponStackEffect  → base[stat] += value × max(0, 同名武器数 - 1)
   · ExplodingEffect    → is_exploding = true

5) 攻速
   atk_spd  = (stat_attack_speed + base.attack_speed_mod) / 100
   cooldown = max(2, base.cooldown × (1/(1+atk_spd)))        若 atk_spd > 0
            = max(2, base.cooldown × (1+|atk_spd|))          否则

6) ★ scaling（属性 → 固定伤害加值）
   scaling_value = Σ over scaling_stats [stat, coef]:
        RunData.current_level × coef      若 stat == "stat_levels"
        Utils.get_stat(stat)  × coef      否则
   damage = max(1, base.damage + scaling_value)

7) ★ 百分比乘区
   pct = 1 + stat_percent_damage / 100
   exp = explosion_damage / 100                  （仅爆炸武器）
   damage = max(1, round(damage × (pct + exp)))

8) crit_damage = base.crit_damage
   crit_chance = base.crit_chance + stat_crit_chance/100
9) accuracy   = base.accuracy  + effects["accuracy"]/100
10) lifesteal = base.lifesteal + stat_lifesteal/100
11) knockback = max(0, base.knockback + effects["knockback"])
12) min_range = base.min_range （effects["no_min_range"] 时为 0）
```

**远程额外**：
```
projectile_spread = base + effects["projectiles"] × 0.1
nb_projectiles    = base + effects["projectiles"]         （仅当 base > 0）
piercing          = base + effects["piercing"]
piercing_dmg_reduction = clamp(base - piercing_damage/100, 0, 1)
bounce            = base + effects["bounce"]
bounce_dmg_reduction   = clamp(base - bounce_damage/100, 0, 1)
```

**结论**：
- `melee/ranged/elemental/engineering` 是 **按武器 scaling 系数的固定加值**（加法）
- `percent_damage` 是 **全局百分比乘区**（乘法）
- **顺序：先加后乘**

#### 计算示例
匕首 T1：`damage=6`，`scaling=[["stat_melee_damage", 0.5]]`
玩家：近战伤害 20，伤害% 30
```
6 + 20×0.5 = 16  →  round(16 × 1.3) = 21
```

### 5.2 命中结算（`unit.gd:202-315` `take_damage`）

```
full = get_dmg_value(value, armor_applied)
       敌人: max(1, value - armor)
       玩家: max(1, round(value × armor_coef))

if dodgeable and randf() < min(dodge, dodge_cap/100):
    full = 0;  is_dodge = true
elif _hit_protection > 0:
    _hit_protection -= 1;  full = 0;  is_protected = true
else:
    flash()                                          ← 闪白 0.1 s

if full != 0 and Utils.get_chance_success(crit_chance):
    full = get_dmg_value(round(value × crit_damage), true, true)   ★ 用原始 value 重算

dmg_dealt = clamp(full, 0, current_health)
current_health = max(0, current_health - full)
_knockback_vector = knockback_direction × knockback_amount
死亡击退 = knockback_direction × max(knockback_amount, 15.0)      ← MIN_DEATH_KNOCKBACK_AMOUNT
```

**★★★ 暴击陷阱**：`round(value × crit_damage)` 用的是**传入的原始伤害**，再走一遍护甲计算，**不是**"已减甲伤害 × 倍率"。对敌人（减法护甲）两种算法结果不同。

#### 额外乘区

| 机制 | 公式 | 源 |
|---|---|---|
| 对 Boss 伤害 | `value × (1 + damage_against_bosses/100)`，在 `take_damage` **之前** | `boss.gd:39-41` |
| 巨人腰带（暴击追伤） | 普通敌人：`+int((当前血量 × giant_crit_damage/100) / max(1, endless_factor×0.2))`<br>Boss：分母改为 `/1000.0` | `enemy.gd:92-108`、`boss.gd:45` |
| 穿透衰减 | `damage = max(1, damage - damage × piercing_dmg_reduction)`（默认 0.5） | `player_projectile.gd:46` |
| 弹射衰减 | 同上，默认 0.5；弹射后 `max_range = 99999`，击退清零 | `player_projectile.gd:66` |

### 5.4 无敌窗口（i-frames）★核心手感

```gdscript
const MIN_IFRAMES = 0.2
const MAX_IFRAMES = 0.4

func get_iframes(damage_taken: float) -> float:
    var pct = damage_taken / max_stats.health
    var mn = MIN_IFRAMES / max(1.0, RunData.get_endless_factor())
    var mx = MAX_IFRAMES / max(1.0, RunData.get_endless_factor())
    return clamp((pct * mx) / 0.15, mn, mx)
```

| 单次受伤占最大血量 | 无敌时长 |
|---|---|
| ≥ 15% | **0.4 s**（满） |
| 11.25% | 0.3 s |
| ≤ 7.5% | **0.2 s**（最低） |

- 触发条件：`dodgeable == true`（**闪避成功也触发**）
- ★ **UE 实现**：受击结算后 Apply `GE_Invincible`（**Duration GE**，时长 = 上式秒数，授予 `State.Invincible`）；
  `GE_Damage` 的 `ApplicationTagRequirements.IgnoreTags` 含该 Tag → 窗口内伤害自动被拒，**伤害公式内无需任何分支**
- `bypass_invincibility = true` 的伤害走不带该 Tag 需求的独立 GE（如 `lose_hp_per_second`）
- **无尽模式下无敌窗口被 `endless_factor` 除，会显著缩短**

### 5.5 击退（`unit.gd:176-183`）

```gdscript
# 原作
func get_next_knockback_value() -> Vector2:
    var value = _knockback_vector * (100 - stats.knockback_resistance * 100)
    _knockback_vector = _knockback_vector.linear_interpolate(Vector2.ZERO, 0.1)   # 每物理帧衰减 10%
    return value

velocity = move_input - knockback_value      ← 减法合入速度
```

★ **UE 侧（帧率无关）**：`Knockback *= FMath::Exp(-6.3216f * DeltaTime)`（`Rate = -60·ln(0.9)`）

- 玩家 `knockback_resistance = 0.0` → 乘 **100**（即 knockback 值 × 100 作为 px/s）
- 衰减：**0.364 s 到 10%，0.728 s 到 1%**（原作 0.37 / 0.73 s，容差内一致）
- 攻击方向取负：`-Vector2(cos θ, sin θ)`
- 敌人被击退期间**暂时关闭其 Hitbox**（`is_being_knocked_back = knockback.length() > move_input.length()`）
- 敌人命中玩家后 `add_decaying_speed(-200)`；`decaying_bonus_speed` 正值以 **−60/s** 衰减、负值以 **+300/s** 回升（原作每帧 −1 / +5）；下限保护 `-(speed×0.8)`，已为负时新增值 `/20`

## 7. 无尽因子（Endless Factor）

`run_data.gd:300-307`：
```gdscript
endless_wave = max(0, wave - 20)
endless_mult = 2.0 + max(0.0, (wave - 35) * 0.2)
endless_factor = max(0.0, ((endless_wave × (endless_wave+1)) / 2) / 100.0) × endless_mult
```
$$EF(W) = \frac{T(W-20)}{100}\cdot\Big(2 + \max(0,(W-35)\times0.2)\Big),\quad T(n)=\frac{n(n+1)}{2}$$

| 波 | 20 | 21 | 25 | 30 | 35 | 40 | 50 | 60 |
|---|---|---|---|---|---|---|---|---|
| **EF** | 0 | 0.02 | 0.30 | 1.10 | 2.40 | 6.30 | 23.25 | 57.40 |
| 敌人 HP `×(1+2.25EF)` | 1.0 | 1.045 | 1.675 | 3.475 | 6.40 | 15.18 | 53.31 | 130.15 |
| 敌人 DMG `×(1+EF)` | 1.0 | 1.02 | 1.30 | 2.10 | 3.40 | 7.30 | 24.25 | 58.40 |
| 敌人 SPD `×(1+min(1.75, EF/13.33))` | 1.0 | 1.0015 | 1.0225 | 1.0825 | 1.180 | 1.473 | 2.744 | **2.75(封顶)** |

> 速度乘子的 1.75 封顶需要 `EF ≥ 23.3275`，即**第 51 波起**才真正触顶（W50 的 EF = 23.25，尚差一点）。

**派生影响**：
- 物价 `× (1 + EF/5)`
- 重掷价 `× √(1+EF)`
- 消耗品掉落率 `/ (1 + EF)`
- 玩家无敌窗口 `/ max(1, EF)`
- 收获每波 **−20%**
- 巨人腰带加成 `/ max(1, EF×0.2)`

## 10. UE5 实现规范

> **本节的实现方案以 [09_UE5实现架构与数据表](09_UE5实现架构与数据表.md) 为准**（分级 GAS 架构）。
> 本节保留的是「无论用什么架构都必须满足的数值契约」。

### 10.1 分层映射（简表，详见 §09 §4）

| 本章概念 | 玩家 / Boss（Tier A/B） | 普通敌人（Tier C） |
|---|---|---|
| BaseValue（`stat_max_hp` = 10，其余 0） | `UAttributeSet` 构造函数 | `FEnemyState` 字段初值 |
| 永久层 `E[s]`（物品/角色/套装/难度） | **Infinite GE + Additive** | 开波时一次性算入 |
| 升级（永久不可撤销） | **Instant GE**（改 BaseValue） | — |
| 波内层 `T[s]` | Infinite GE + Tag `Effect.Lifetime.Wave` | 固定 slot |
| 联动层 `L[s]`（每 N 点 X 给 Y） | Infinite GE + Tag `Effect.Lifetime.Linked`，脏时移除重建 | — |
| `gain_xxx` 乘区 | **Multiplicative + AttributeBased 非快照** Modifier | 开波时算入 |
| `hp_cap` / `dodge_cap` / `speed_cap` / `weapon_slot` | **`EGameplayModOp::Override`** | 常量 |
| 数组钩子槽（36 个） | `UBrotatoHookRegistry`（非 GAS） | 共享同一 Registry |
| 规则开关（bool） | `GameplayTag`（`Rule.*` loose tag） | 位标记 |

**数学等价性**：GAS 的 `CurrentValue = (BaseValue + ΣAdditive) × ΠMultiplicative` 与本章公式
$\big(E[s]+T[s]+L[s]\big)\cdot\big(1+\frac{E[\text{gain\_}s]}{100}\big)$ **完全等价**。

### 10.2 ★ 必须逐条对齐的数值契约（架构无关）

| 项 | 要求 |
|---|---|
| 取整时机 | `damage` 在 scaling 后 `max(1, ...)` 取一次，乘 pct 后 `max(1, round(...))` 再取一次 |
| **舍入方向** | Godot `round()` = **half away from zero**（`round(-0.5) = -1`）；UE `FMath::RoundToInt()` = **half to +∞**（`= 0`）。**必须自写 `BrotatoRound()`**，见 §09 §2.5 |
| **浮点 → 整数** | Godot `as int` / `int()` = **截断向零**，不是 `floor`。负值场景差 1，见 §09 §2.5 |
| 随机数比较符 | 闪避 `<`；`get_chance_success` 用 `<=` 且 `chance == 0 → false` |
| `randf()` 范围 | `[0, 1)`，UE 用 `FRandomStream::FRand()`（同为 `[0,1)`） |
| 随机数来源 | `FRandomStream` **按用途分流**（Shop/Loot/Spawn/Combat/Cosmetic）；GAS 的 ExecCalc / MMC 内**禁用** `FMath::FRand()`，须取 `Combat` 流（§00 §5.2） |
| 护甲双公式 | 玩家乘法 / 敌人减法，**分开实现**，用 `bIsPlayer` 分支，不要抽象成同一个 |
| 暴击 | 传**原始值**重算，不是已减甲值 × 倍率 |
| 冷却单位 | **float 秒**，`max(1/30, ...)`；Cooldown GE 在攻击序列结束时施加（等价于"射击中不递减"，§00 §3.2） |
| 整数除法 | LinkedStats 的 `scaled / nb` 必须 `FMath::FloorToInt` |
| gain 乘区 | 三层相加后统一乘一次（GAS 的 Multiplicative 天然满足） |
| LinkedStats 源属性 | **必须排除 Linked 层本身**（否则循环依赖自我放大） |
| 脏标记 | 属性变更只置脏，**Tick 末统一重算**（模拟阶段 S11）武器 stats + 重建 Linked GE + 广播 UI |
| 公式唯一性 | 所有公式只写在 `FBrotatoDamageMath`（`BrotatoCore`），GAS 侧与纯函数侧共享调用 |
