# 10 · 开发排期与验收清单

> 总周期估算：**20 周**（单人全职约 30–36 周；3 人小队约 20 周）
> 前置假设：美术与音频并行外包/自制，程序不阻塞于资源。

## 1. 里程碑总览

| 阶段 | 名称 | 周期 | 依赖 | 核心产出 |
|---|---|---|---|---|
| **M0** | 技术验证 | 1 周 | — | 固定 60Hz Tick、正交相机、200 单位压测 |
| **M1** | 可玩核心 | 3 周 | M0 | 移动 + 1 武器自动攻击 + 1 敌人 + 单波 + 死亡 |
| **M2** | 数值骨架 | 2 周 | M1 | 完整属性系统 + 全伤害公式 + 升级 + 材料/XP |
| **M3** | 构筑闭环 | 3 周 | M2 | Effect 框架 + 商店 + 30 物品 + 武器合成 + 套装 |
| **M4** | 内容填充 | 4 周 | M3 | 20 波配表 + 全敌人 + Boss/精英 + 全武器 + 全物品 |
| **M5** | 角色与元进度 | 3 周 | M4 | 44 角色 + 88 挑战 + 解锁 + 存档 + 续关 |

**关键路径**：M0 → M1 → M2 → **M3（Effect 框架）** → M4 → M5
**最大风险点**：M3 的 Effect 框架。它是 179 物品 + 44 角色 + 15 套装的共同底座，设计错误会导致 M4/M5 大面积返工。**建议 M3 结束设强制评审关卡。**

### 1.1 GAS 学习节奏叠加

本项目采用**分级 GAS**架构（见 [09](09_UE5实现架构与数据表.md)）。GAS 特性按下表分批引入，**不要一次性全上**：

| 阶段 | 新引入的 GAS 特性 | 说明 |
|---|---|---|
| M0 | `UAbilitySystemGlobals` 子类、GameplayTag 字典、ASC 默认 Tick + Duration/Periodic/Cooldown GE 各验一例 | 先把地基铺好 |
| M1 | `UGameplayAbility`（武器攻击）、`UAbilityTask`（挥击时序，Ticking）、**Cooldown GE + SetByCaller**、**Duration GE**（无敌窗口） | 只求跑通，不求完美 |
| M2 | `UAttributeSet` ×4、`PreAttributeChange` clamp、Instant vs Infinite GE、`UGameplayEffectExecutionCalculation`（伤害）、Meta Attribute、**Periodic GE**（生命回复/燃烧） | **数值正确性优先** |
| M3 | Infinite GE 增删、AttributeBased 非快照 Modifier（`gain_*`）、`Override` Modifier、`RemoveActiveEffectsWithGrantedTags`、自定义 MMC + LinkedStats 移除重建 | ★ GAS 最密集的阶段 |
| M4 | GameplayEvent + Triggered Ability（爆炸/召唤类钩子）、Boss 的 Tag 状态机 | 把 3–5 个钩子从「直接遍历」重构成 Ability |
| M5 | GE Stacking（受击叠加）、自定义 `FGameplayEffectContext`（伤害来源统计）、存档时 GE 重建策略 | |
| M6 | `UGameplayCueNotify_Burst` / `_Looping`、**Cue Proxy ASC**、Cue 预加载 | 表现层统一走 Cue |

> **重要**：M2 的目标是"**数值 100% 正确**"，不是"GAS 用得漂亮"。若某处 GAS 映射阻塞进度，先用纯函数跑通并标 `// TODO: GAS`，M3/M4 再回来重构。**不要让学习目标拖垮复刻目标。**
