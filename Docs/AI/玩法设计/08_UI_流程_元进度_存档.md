#### Text（本地化格式化器）
```gdscript
func text(key, args = [], arg_signs = []) -> String:
    1. key == "[EMPTY]" → ""
    2. tr(key) 取译文
    3. 若该 key 需要运算符且译文里没有 {0}，自动在前面拼 "{0} "
    4. 逐个 {i} 替换；按 arg_signs[i] 包 [color=#00ff00] / [color=red]
    5. 按 keys_needing_operator[key] 给指定下标加 "+"（int(v) >= 0 时）
    6. 按 keys_needing_percent[key] 给指定下标加 "%"
```
两张映射表 `keys_needing_operator`（~80 项）与 `keys_needing_percent`（~70 项），value 是**需要处理的参数下标数组**，如 `"effect_weapon_stack": [0,3]`。

> **UE5 对照**：需要一张「本地化键 → 参数格式规则」的 DataTable，而不是把 `+`/`%` 写进译文。

## 2. 游戏流程状态机

### 2.1 完整时序

见 [01_核心玩法与循环设计](01_核心玩法与循环设计.md) §3。此处补充关键分支：

```
[TitleScreen]
  StartButton    → MusicManager.tween(-5) → character_selection
  ContinueButton → RunData.resume_from_state(ProgressData.current_run_state) → shop
  Options/Progress/Mods/Credits → 同场景内页面切换（hide/show + to.init()，无动画）
  Quit → get_tree().quit()

[CharacterSelection]
  ui_cancel → current_zone=0, reload_music=false → title_screen
  按下 → RunData.add_character(...)
        effects["weapon_slot"] == 0 ? → difficulty_selection : → weapon_selection

[WeaponSelection]
  可选项 = current_character.starting_weapons ∩ ProgressData.weapons_unlocked
  is_locked_elements_displayed() = false（不显示未解锁的初始武器）
  ui_cancel → RunData.apply_weapon_selection_back()（清 weapons/items/effects，回角色选择）
  按下 → add_weapon(is_starting=true) + add_starting_items_and_weapons() → difficulty_selection

[DifficultySelection]
  可选项 = value <= max_selectable_difficulty 的难度
  初始焦点 = difficulty_selected_value（记忆）
  EndlessButton 与 Inventory 用 focus_neighbour 拼接
  ui_cancel → 清 weapons/items/effects/is_endless_run/set 效果 → 重新 add_character → 回武器选择
  按下 → difficulty_selected_value = value; RunData.current_difficulty = value
         RunData.init_elites_spawn(); ProgressData.save(); 应用 difficulty.effects
         MusicManager.tween(0)
         current_run_accessibility_settings = settings.enemy_scaling.duplicate()
         → main.tscn

[Main → EndWaveTimer 超时]
  run_lost || run_won || is_last_wave → end_run.tscn（is_testing → editor.tscn）
  否则 → MusicManager.tween(-8)
        → 逐个 ItemBoxUI（yield）→ 逐个 UpgradesUI（yield）→ 挑战弹窗（yield）
        → shop.tscn

[Shop]
  GoButton → save_run_state → current_wave += 1 → MusicManager.tween(0) → main.tscn
  EndlessButton（仅 W==19 且未开无尽）→ is_endless_run = true 后同 Go

[EndRun]
  Retry  → RunData.reset(true); MusicManager.play(0) → main.tscn（同角色同武器重开）
  NewRun → Utils.last_elt_selected = current_character; RunData.reset(); tween(-5) → character_selection
  Exit   → RunData.reset() → title_screen
```

### 2.3 波次结束流程

```
_on_WaveTimer_timeout():
  1. log_run_info()
  2. is_last_wave() → 未失败且最后一波 → _is_run_won = true
  3. ChallengeService.check_counted_challenges()
  4. chal_reckless 检查（player.health == chal.value）
  5. chal_forest 检查（neutrals.size() >= chal.value）
  6. stats_end_of_wave 结算（记录 item_vigilante_ring / item_grinds_magical_leaf 追踪值）
  7. convert_stats_end_of_wave
  8. manage_harvesting()
  9. clean_up_room(is_last_wave, false, _is_run_won)
 10. 胜利 → apply_run_won()
 11. EndWaveTimer.start(); TempStats.reset(); InputService.hide_mouse = true
```

`clean_up_room()`：
```
失败：停 WaveTimer/TickTimer、EndWaveTimer=2.5、播失败音、DimScreen.dim()、Music.tween(-20)
胜利：apply_run_won()
无尽：W%10==0 && >=20 → init_elites_spawn(W, 0.0)；W>=20 → 写 max_endless_wave_beaten
ProgressData.save()（非 testing）
_cleaning_up = true；EffectsManager / FloatingTextManager 清理
金币吸附（或 optimize_end_waves 直接换算）；消耗品飞向玩家
EntitySpawner.clean_up_room() / WaveManager.clean_up_room() / _player.clean_up()
WaveClearedLabel.start()
```

`apply_run_won()`（★ 元进度写入点）：
```
停计时器；EndWaveTimer = 3；DimScreen.dim()；播胜利音
complete_challenge("chal_" + character.name.to_lower().replace("character_",""))
若 max_selectable_difficulty < cur+1 且 cur+1 <= 5 → RunData.difficulty_unlocked = cur+1
complete_challenge("chal_difficulty_" + str(cur))

```

死亡流程：
```

  PlayerLifeBar.hide()
```

### 2.4 暂停规则

- `PauseMenu` 的 `pause_mode = PAUSE_MODE_PROCESS`，挂在 `main.tscn` 的 `UI` 与 `shop.tscn` 下
- `_input`：`(ui_cancel || ui_pause) && paused` → `manage_back()`；否则 `ui_pause` → `pause()`
- `pause()`：emit `paused` → `show()` → `tree.paused = true` → `_main_menu.init()`
- `unpause()`：`hide()` → `paused=false` → `_menus.reset()` → emit `unpaused`
- `on_game_lost_focus()`：若 `settings.pause_on_focus_lost`（默认开）→ 自动 `pause()`
- `main.gd` 响应：`paused → reload_stats()`；`unpaused → on_focus_lost()`（焦点还给 ItemBoxUI/UpgradesUI）
- `shop.gd`：`on_paused → save_run_state + Content.hide()`；`on_unpaused → show() + on_focus_lost()`
- 常驻 PROCESS：`InputService`、`CursorManager`、`SoundManagerParent`、`MusicManager`

#### 2.4.1 ★ UE5 暂停语义对照表

`UGameplayStatics::SetGamePaused(true)` 会停掉绝大多数 Tick，但**以下必须继续工作**（对齐原作 `pause_mode = PROCESS` 白名单）：

| 对象 | 暂停时行为 | UE 实现 |
|---|---|---|
| `UBrotatoSimSubsystem` | **停止全部模拟阶段** | `SetPaused(true)`，配合 `SetGamePaused` |
| 输入服务 | **继续** | `PrimaryActorTick.bTickEvenWhenPaused = true`；Enhanced Input 用 `bExecuteWhenPaused` |
| 光标管理 | **继续** | 同上 |
| SFX / 音乐 | **继续**（音乐仍淡变） | Submix 不暂停；`UAudioComponent::bIsUISound = true` |
| 暂停菜单 UI | **继续** | CommonUI Widget 默认不受暂停影响；动画用 `WidgetAnimation` 而非 Timer |
| Niagara 特效 | **暂停** | 默认行为即可 |
| GameplayCue 播放 | **暂停**（新 Cue 不派发） | 限流入口在暂停时直接 return |
| **ASC 的 GE 计时**（Duration / Periodic / Cooldown） | **自动暂停** ✅ | ★ GE 走 World 时间，`SetGamePaused` 时天然停走 —— 无需任何额外代码 |
| `FTimerManager` / `UAbilityTask_WaitDelay` | **自动暂停** ✅ | 同上（World Timer） |

> **验收**：暂停时敌人/子弹/计时全停；ESC 可再次唤起；音乐继续淡变；
> ★ 暂停 5 s 后恢复，**无敌窗口 / 燃烧 / 武器冷却的剩余时长不减少**（§00 §2.5、D06 U19）。

### 2.5 菜单页面状态机

```gdscript
class Menus extends Control          # 信号 menu_page_switched(from, to)
switch(from, to): from.hide(); to.show(); to.init(); _current_page = to
back():  _current_page != _main_menu → switch(_current_page, _main_menu)
reset(): switch(_current_page, _main_menu)
```
- `TitleScreenMenus`：额外 `MenuCredits / MenuMods / ProgressionUI`
- `IngameMenus`：额外 `MenuConfirm`（退回标题确认）/ `MenuRestart`（重开确认）
- **页面切换是瞬时 hide/show，无 Tween**

### 5.2 备份与恢复策略

```

  save.json 坏 → CORRUPTED_SAVE       → 读 save_latest.json
```

序列化规则：

- `current_background` → `name.to_lower()`；`current_character/starting_weapon` → `my_id`

### 5.3.1 ★ 存档版本迁移策略

`merge_dictionaries` 只能解决"**新增键带默认值**"，无法处理键重命名、语义变更、id 变更。UE5 侧必须补一条迁移管线。

```cpp
// BrotatoSave
UCLASS() class UBrotatoSaveGame : public USaveGame
{
    UPROPERTY() int32 SaveVersion = CurrentSaveVersion;   // ★ 独立于游戏版本号
    // ... 12 个数据块
};

static constexpr int32 CurrentSaveVersion = 1;

/** 逐版本串行迁移：1→2→3…，绝不跨版本跳跃 */
bool UBrotatoSaveSubsystem::Migrate(UBrotatoSaveGame* Save)
{
    while (Save->SaveVersion < CurrentSaveVersion)
    {
        switch (Save->SaveVersion)
        {
        // case 1: Migrate_1_to_2(Save); break;
        default: return false;   // 未知版本 → 视为损坏，走三级备份恢复
        }
        ++Save->SaveVersion;
    }
    return true;
}
```

**必须准备的迁移工具**：

| 场景 | 方案 |
|---|---|
| 物品/武器 **id 重命名** | `DT_IdRemap`（`OldId → NewId`），在反序列化解析 `my_id` 前统一过一遍 |
| 物品**被删除** | `DT_IdRemap` 映射到 `NAME_None` → 静默丢弃（不可让整档解析失败） |
| 设置项**语义变更**（如 bool → enum） | 在对应 `Migrate_N_to_N+1` 里显式转换 |
| `run_state` **结构变更** | **直接丢弃 `run_state`**（续关是易失数据），保留解锁与统计 |
| 未来新增字段 | 继续用 `merge_dictionaries(默认值, 存档值)`，无需迁移 |

**铁律**：
1. `SaveVersion` 与游戏 `version` 字段**分离**（游戏版本变但存档结构不变时不应触发迁移）。
2. 迁移**只增不减**：解锁列表永不因迁移而减少。
3. 迁移失败 → 走 §5.2 的三级备份级联，**绝不写回损坏档**。
4. 每次改存档结构必须：`++CurrentSaveVersion` + 写 `Migrate` 分支 + 补一条"旧档读入"回归测试。

## 6. 本地化与资源命名规范

### 6.1 本地化

- 13 语言，单一源表 `resources/translations/translations.csv`（**本反编译仓库中已丢失，需重建**）
- Steam 语言映射：`english→en, french→fr, schinese→zh, tchinese→zh_TW, japanese→ja, koreana→ko, russian→ru, polish→pl, spanish→es, brazilian→pt, german→de, turkish→tr, italian→it`

**键命名规范**：

| 前缀/模式 | 用途 | 例 |
|---|---|---|
| `STAT_*` | 主属性名 | `STAT_MAX_HP` |
| `INFO_POS_*` / `INFO_NEG_*` | 属性 Tooltip（按正负分支） | `INFO_POS_STAT_ARMOR` |
| `INFO_*_LIMITED` | 有上限/衰减的变体 | `INFO_POS_STAT_HARVESTING_LIMITED` |
| `EFFECT_*` | 道具/武器效果描述 | `EFFECT_WEAPON_STACK` |
| `CHAL_*` / `CHAL_*_DESC` | 挑战标题与描述 | `CHAL_HOARDER`, `CHAL_CHARACTER_DESC` |
| `CHARACTER_*` | 角色名（同时是挑战 name） | `CHARACTER_WELL_ROUNDED` |
| `ITEM_*` / `TIER_*` / `CATEGORY_*` | 道具名 / 品质 / 分类 | `ITEM_BAIT`, `TIER_LEGENDARY` |
| `MENU_*` | 菜单文本 | `MENU_SHOP`, `MENU_GO`, `MENU_RECYCLE` |
| `LANGUAGE_*` | 语言名 | `LANGUAGE_ZH` |
| `PCT_*` / `CHANCE_*` | 百分比型次级属性显示名 | `PCT_ENEMY_SPEED` |
| 战斗内 | `WAVE`, `RUN_WON`, `RUN_LOST`, `LEVEL_UP`, `DODGE`, `NULLIFIED`, `MUTATION` | |
| `[EMPTY]` | 特殊标记 → 返回空串 | |

### 6.2 ★ 资源 ID 规范（双 ID 体系）

| 资源 | 目录 | `my_id` | 分组 ID | 解锁字段 |
|---|---|---|---|---|
| 角色 | `items/characters/<name>/` | `character_<name>` | — | `characters_unlocked`（my_id） |
| 道具 | `items/all/<name>/`（~179） | `item_<name>` | — | `items_unlocked`（my_id） |
| 武器 | `weapons/{melee,ranged}/<name>/<1-4>/` | `weapon_<name>_<1..4>` | **`weapon_id = "weapon_<name>"`** | `weapons_unlocked`（**weapon_id**，一次解锁 4 阶） |
| 升级 | `items/upgrades/<stat>/<1-4>/` | `upgrade_<stat>_<1..4>` | **`upgrade_id = "upgrade_<stat>"`** | `upgrades_unlocked`（**upgrade_id**） |
| 消耗品 | `items/consumables/<name>/` | `consumable_<name>` | — | `consumables_unlocked` |
| 挑战 | `challenges/<name>_data.tres`（88） | `chal_<name>` / `unlock_difficulty_<N>` | — | `challenges_completed`；同时是 Steam 成就 ID |
| 难度 | `items/difficulties/<N>/` | `difficulty_<N>` | — | `max_selectable_difficulty`（数值） |
| 区域 | `zones/zone_<N>/` | `my_id` 是 **int** | — | `zones_unlocked`（int） |
| 套装 | `items/sets/*` | 字符串 | — | 无需解锁 |
| 属性图标 | `StatData{stat_name, icon, small_icon}`（19 项） | `stat_name` = effects 键 | — | — |

**命名不一致警告**：
- `weapons/melee/cactus_mace/` 的 `my_id = "weapon_cacti_club_1"`，`weapon_id = "weapon_cacti_club"`
- `weapons/melee/knuckles/` 的 `weapon_id = ""`（特殊武器，不进商店池）
- tier 1 文件名通常不带后缀（`knife_data.tres`），tier 2-4 带（`knife_2_data.tres`），但 `my_id` 都带 `_1..4`
