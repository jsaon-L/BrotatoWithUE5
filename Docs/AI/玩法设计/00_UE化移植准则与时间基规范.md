## 1. 为什么要有这份准则

第一轮文档是在「逐文件逆向 Godot 3.5 源码」的基础上写成的，因此把**原作的引擎实现细节**也一并当成了复刻目标，典型表现：

| 原作实现细节 | 第一轮文档的处理 | 问题 |
|---|---|---|
| 冷却单位是 60 Hz 物理帧（`cooldown=60` 即 1 s） | 全工程用 `int32 CurrentCooldownFrames`，要求固定 60 Hz 逻辑 Tick | 把 Godot 的 `_physics_process` 语义搬进 UE，与 UE 的时间模型、GAS、Timer、动画、Niagara 全部割裂 |
| `set_deferred("disabled")` 产生 1 帧延迟 | 要求 UE 侧复刻「延迟 1 帧生效」 | 复刻的是 Godot 的 bug/副作用，不是设计意图 |
| 燃烧 `duration` 是 tick 数 | 要求用整数 tick 计数器，**禁用 Periodic GE** | 主动阉割 GAS 最标准的能力，与「学习 GAS」的项目目标自相矛盾 |
| `lerp(→0, 0.1)` 每帧击退衰减 | 要求固定帧才能收敛一致 | 帧率相关写法；UE 侧有帧率无关的标准解 |
| 全局单一 RNG，按调用顺序取数 | 要求逐帧确定性 | 逐帧确定性在 UE 里成本极高，而项目真实需求只是「同 seed 同掉落/同商店」 |

**结论**：复刻目标应当是 **玩家可观测的行为与手感**，不是**宿主引擎的实现方式**。

### 1.1 ★ 三条根本原则

| # | 原则 | 含义 |
|---|---|---|
| **P1** | **行为等价，而非帧等价** | 验收对象是可观测量：攻击间隔（秒）、TTK、DPS、无敌窗口时长、屏震时长与幅度。容差 **±2%** 或 **±1 帧@60fps**，取宽者 |
| **P2** | **时间即时间** | 所有时间量的**唯一权威单位是秒（float）**。帧数只作为「原作出处注释」存在，不进入任何运行时字段、不进入任何数据表列 |
| **P3** | **优先用引擎给的东西** | 有 UE / GAS 原生机制可用时，不自建平行设施。自建只允许发生在「原生机制确实表达不了」且**在本文档 §9 登记豁免**的地方 |

## 2. 时间基规范（★ 全工程强制）

### 2.1 单位表

| 量 | 单位 | 类型 | 说明 |
|---|---|---|---|
| 时间 / 冷却 / 时长 / 间隔 | **秒** | `float` | 数据表、DataAsset、蓝图、UI 全部用秒 |
| 一局累计时长 | 秒 | `double` | 长时长累加避免 float 精度漂移 |
| 距离 / 尺寸 | **uu（cm）** | `float` | `1 原作 px = 1 uu`，数值直接沿用 |
| 速度 | uu/s | `float` | `450 px/s → 450 uu/s` |
| 角速度 | **度/秒** | `float` | 原作「每帧 +25°」→ `1500 °/s` |
| 概率 | 0–1 | `float` | 数据表存百分数时由导入器 /100 |
| 伤害 / HP / 材料 / 金币 / 等级 / 数量 | 整数 | `int32` | ★ 仍保留整数语义与 Godot 取整契约（§6） |

### 2.2 帧 → 秒 换算契约

导入器（`BrotatoEditor` 的 `.tres` Commandlet，见 D07）在**导入期**完成换算，运行时**不存在帧值**：

```
Seconds = Frames / 60.0        // 精确除，不取整、不截断
```

常用换算（便于对照原文档旧表）：

| 原作帧 | 秒 | 出现处 |
|---|---|---|
| 1 | 0.0167 | Drill / Minigun / Chain Gun / Gatling 冷却 |
| 2 | 0.0333 | ★ 冷却硬下限 |
| 3 | 0.05 | 地雷命中窗口 |
| 4 | 0.0667 | SMG 冷却 |
| 6 | 0.1 | 吸血 CD / 受击闪白 |
| 10 | 0.1667 | 冷却贴图恢复阈值 |
| 22 / 27 | 0.3667 / 0.45 | Dagger IV / I 冷却 |
| 30 | 0.5 | 燃烧 tick 间隔 |
| 40 | 0.667 | 收获结算延迟 |
| 60 | 1.0 | 大装填基准 / 离屏销毁 |
| 180 | 3.0 | 地雷存在时长 |
| 300 | 5.0 | 周期性临时属性叠加 |

> **原文档中所有形如「N 帧」的表述，等价读作「N/60 秒」。** 各章遗留的帧数标注保留为溯源信息，前缀统一为 `原作 N 帧`。

### 2.3 时间推进模型（取代 `FixedTickSubsystem`）

**决议：取消强制固定 60 Hz 逻辑帧，回归 UE 标准的可变 `DeltaTime` 推进。**

| 层级 | 机制 | 说明 |
|---|---|---|
| 模拟阶段编排 | 单一 `UBrotatoSimSubsystem`（`UWorldSubsystem` + `FTickableGameObject`），在其 `Tick(DeltaTime)` 内按**固定阶段顺序**推进（见 §2.4） | 用「阶段顺序」替代「固定步长」来保证逻辑一致性 |
| Actor 级 | 正常 `AActor::Tick` / `UActorComponent::Tick`，必要时用 `TickGroup` + `AddTickPrerequisiteComponent` 表达依赖 | 不再自建 `IFixedTickable` 注册表 |
| 属性/状态计时 | **GAS 原生**：Duration / Periodic GE、Cooldown GE、`UAbilityTask` | 见 §3 |
| 一次性延迟 | `UAbilityTask_WaitDelay` / `FTimerManager::SetTimer` | 受 Pause 与 TimeDilation 正确影响 |
| 大批量非 Actor 实体（子弹 / 材料 / 飘字） | 在各自 Subsystem 的批处理循环里 `Remaining -= DeltaTime` | 数据仍是 SoA 数组 |

**帧率无关写法的两条硬规则**：

1. **任何随时间变化的量都必须乘 `DeltaTime`**，禁止「每 Tick 减 1 / 每 Tick ×0.9」这类隐含 60 Hz 的写法。
2. **指数衰减用半衰期形式**。原作「每帧 `lerp(→0, 0.1)`」的 UE 等价写法：

```cpp
// 原作：每物理帧 v = lerp(v, 0, 0.1)  → 60 Hz 下每帧 ×0.9
// 帧率无关等价式（衰减常数由 60·ln(0.9) 推出）
namespace BrotatoConst
{
    constexpr float KnockbackDecayRate = 6.3216f;   // 1/s，= -60 * ln(0.9)
}
Velocity *= FMath::Exp(-BrotatoConst::KnockbackDecayRate * DeltaTime);
// 校验：t=0.364 s 剩 10%，t=0.728 s 剩 1% —— 与原作 0.37 s / 0.73 s 一致（P1 容差内）
```

> 通用换算：原作「每帧 ×k」→ `Rate = -60 * ln(k)`，UE 侧 `Value *= FMath::Exp(-Rate * DeltaTime)`。

### 2.4 模拟阶段顺序（★ 固定不可变，取代「16 步逻辑帧」）

顺序依旧固定，但每一步接收的是真实 `DeltaTime`，而非 1/60：

| 阶段 | 内容 | 归属 |
|---|---|---|
| S1 | 输入采样（`EnhancedInput`） | Gameplay |
| S2 | `WaveManager` 推进（波次计时、刷怪组触发） | Gameplay |
| S3 | `EntitySpawner` 分摊生成（**按秒节流**：5 条队列、每队列 `1 / 0.05 s` = 20 个/s） | Gameplay |
| S4 | 移动行为求解 → 期望速度合成 | Gameplay |
| S5 | 位移与碰撞解算（`SafeMoveUpdatedComponent` / 批量 Overlap） | Gameplay |
| S6 | 击退与外力衰减（指数衰减，§2.3） | Gameplay |
| S7 | 武器：选靶 → `TryActivateAbility` / `FWeaponFireCore::Fire()` | GAS / Gameplay |
| S8 | 投射物批更新 | Gameplay |
| S9 | 命中判定 → 伤害结算（Tier A/B 走 GE，Tier C 走纯函数管道） | GAS / Gameplay |
| S10 | 拾取吸附与结算 | Gameplay |
| S11 | 属性脏标记统一处理（LinkedStats 重算 → 武器 RuntimeStats 重算 → 广播 UI） | GAS / UI |
| S12 | 死亡清理与对象回收 | Gameplay |
| S13 | 表现层提交（Cue / 飘字 / 屏震 / 音效） | GAS / UI |

**与旧「16 步」的差异**：
- 删除「冷却帧计数递减」步 —— 冷却交给 Cooldown GE（§3.2）。
- 删除「状态效果帧推进」步 —— 燃烧 / 回血 / 掉血 / 吸血 CD 交给 Periodic / Duration GE（§3.3）。
- 删除「`ASC.FixedTickASC()`」步 —— ASC 恢复引擎默认驱动，**不得关闭其 Tick**。
- 删除「每 3 帧 / 每 60 帧」这类计数节流 —— 改为按秒的累加器节流。

### 2.5 暂停与时间缩放

- 波间商店、升级弹窗等：用 `UGameplayStatics::SetGamePaused` 或对模拟对象设 `CustomTimeDilation = 0`。
- GE 的 Duration / Period 走 World 时间，**天然随 Pause 与 TimeDilation 正确停走**，这是改用原生计时后白送的收益（旧方案需要手写「暂停清零、恢复不补帧」）。
- 原作无 `time_scale` / 帧冻结逻辑（§04 §9），本项目也不引入命中顿帧。

## 3. GAS 使用规范（★ 解除旧文档的全部禁令）

### 3.1 GE 类型使用边界（取代 §09 §2.2 / D03 的禁令表）

| GE 类型 | 状态 | 用途 |
|---|---|---|
| **Instant** | ✅ 使用 | 伤害、治疗、永久升级、一次性属性变更 |
| **Infinite** | ✅ 使用 | 物品 / 角色 / 套装 / 难度 / 常驻被动的属性修正（显式 Remove） |
| **Duration** | ✅ **使用**（旧文档禁止，现解禁） | 无敌窗口、吸血 CD、临时 Buff、减速、状态 Tag 的授予 |
| **Periodic** | ✅ **使用**（旧文档禁止，现解禁） | 燃烧 tick、生命回复、`lose_hp_per_second`、每 5 s 临时属性叠加 |
| **Cooldown GE** | ✅ **使用**（旧文档禁止，现解禁） | 武器攻击冷却、结构物开火冷却 |

**实现要点**：
- Duration 由调用方决定时：GE 的 `Duration Policy = HasDuration`，`Duration Magnitude = SetByCaller`，运行时 `Spec->SetSetByCallerMagnitude(Tag_Data_Duration, Seconds)`。
- Period 需要运行时可变时（燃烧缩减）：`FGameplayEffectSpec::Period` 在 Apply 前可直接写；避免为每档间隔各做一个 GE 资产。
- 叠加语义用原生字段表达：`StackingType` / `StackLimitCount` / `StackDurationRefreshPolicy` / `StackPeriodResetPolicy`，不要自建叠层数组。

### 3.2 武器冷却 = Cooldown GE（★ 旧决议反转）

旧文档以三条理由拒绝 Cooldown GE，逐条给出 UE 原生解法：

| 旧理由 | UE 原生解法 |
|---|---|
| 「单位是整数帧，Duration 是 float 秒」 | 秒才是正解（P2）。硬下限 `2 帧` → 常量 `MinWeaponCooldown = 1.f/30.f` |
| 「每次射击有随机抖动，SetByCaller 太绕」 | 这正是 `SetByCaller` 的标准用法：重写 `UGameplayAbility::ApplyCooldown`，在 Spec 上写入本次抖动后的秒数 |
| 「射击过程中冷却不递减」 | **在攻击序列结束时才 Apply Cooldown GE**。原作「开火时设定冷却 + 射击期间不递减」与「射击结束后开始计时」**数学等价**，且更符合 GAS 语义 |
| 「攻速变化要立即压缩当前冷却」 | `RemoveActiveGameplayEffectBySourceEffect` + 重新 Apply 剩余时长；或直接 `ModifyActiveGameplayEffectStartTime`（GAS 原生支持修改剩余时长） |

```cpp
// UGA_WeaponAttack
virtual void ApplyCooldown(const FGameplayAbilitySpecHandle Handle,
                           const FGameplayAbilityActorInfo* ActorInfo,
                           const FGameplayAbilityActivationInfo ActivationInfo) const override
{
    const UGameplayEffect* CooldownGE = GetCooldownGameplayEffect();
    if (!CooldownGE) return;

    FGameplayEffectSpecHandle Spec = MakeOutgoingGameplayEffectSpec(CooldownGE->GetClass(), 1.f);
    // ★ 秒；含随机抖动与大装填，公式见 §04 §7.4（已秒化）
    Spec.Data->SetSetByCallerMagnitude(BrotatoTags::Data_Cooldown, NextCooldownSeconds);
    // 供 UI 与 Hook 查询的槽位 Tag
    Spec.Data->DynamicGrantedTags.AddTag(BrotatoTags::Cooldown_Weapon_Slot(SlotIndex));
    ApplyGameplayEffectSpecToOwner(Handle, ActorInfo, ActivationInfo, Spec);
}
```

- UI 进度条：`ASC->GetActiveGameplayEffectRemainingDuration()` / `GetCooldownTimeRemaining()`，不再自己维护倒计时。
- Tier C（炮塔、无 ASC 敌人）：在其批处理结构体里用 `float CooldownRemaining -= DeltaTime`，公式仍调用 `FWeaponFireCore`，与 Tier A 共享同一份秒制公式。

### 3.3 状态计时的原生映射表（取代所有 `int32 *FramesLeft` 字段）

| 机制 | 旧方案 | ★ 新方案 |
|---|---|---|
| 无敌窗口（0.4 / 0.3 / 0.2 s） | `InvincibilityFramesLeft` | Duration GE 授予 `State.Invincible`；`GE_Damage` 用 `ApplicationTagRequirements.IgnoreTags` 直接拒绝 —— **无需在伤害公式里写 if** |
| 吸血 CD（0.1 s） | `LifestealCdFramesLeft` | Duration GE 授予 `State.LifestealCd`，同样用 Tag 需求拦截 |
| 受击闪白（0.1 s） | `FlashFramesLeft` | GameplayCue（Timed）或 `UMaterialInstanceDynamic` + Timeline/Timer |
| 燃烧（N 次 × 间隔 T） | `BurnTickFramesLeft` + tick 计数 | Periodic GE：`Period = T`、`Duration = N * T`（均 SetByCaller），`StackDurationRefreshPolicy` 表达「刷新不叠层」 |
| 生命回复 / `lose_hp_per_second` | 帧计数器 | Periodic GE（Period = 1 s），Magnitude 走 MMC 读当前属性 |
| 每 5 s 临时属性叠加 | 每 300 帧 `AddStack` | Periodic GE：`Period = 5`，`StackingType = AggregateBySource` + `StackLimitCount` |
| 结构物生成检查（原每 60 帧） | 帧计数器 | Periodic GE 或 `FTimerManager` 1 s 循环 |
| Hitbox 启/停的「1 帧延迟」 | 刻意延迟 1 帧 | ❌ **不复刻**。改为立即生效 + `TSet<AActor*> IgnoredThisSwing` 去重（这才是原作 `set_deferred` 想达到的效果） |
| 子弹出膛延迟（原 2 帧） | `DelayFramesBeforeMove = 2` | `float LaunchDelay = 0.02f`（秒），在批更新里累减 |

### 3.4 其他 GAS 相关决议

| 项 | 决议 |
|---|---|
| ASC Tick | **保持引擎默认开启**，禁止 `SetComponentTickEnabled(false)` + 手动驱动 |

| 卸载句柄 | 仍强制用 `FActiveGameplayEffectHandle`，不做值比较（原作此处有 bug，不复刻） |

| 子系统 | 旧方案 | ★ 新方案 | 理由 |
|---|---|---|---|
| 玩家移动 | 自建位移积分 | `UFloatingPawnMovement`（高 Acceleration/Deceleration 近似瞬时响应）或自定义 `UPawnMovementComponent` + `SafeMoveUpdatedComponent` | 拿到 UE 的 sweep/滑移/根组件更新；仍保持无惯性手感（P1 只要求观测等价） |

| 敌人 AI | 枚举 `MovementBehaviorType + AttackBehaviorType` 批处理 | 小兵：保留数据驱动批处理（性能需要）；**Boss / 精英 / 结构物改用 `StateTree`** | StateTree 是 UE5 原生轻量状态机，正是 Boss 阶段机的标准答案；BT 才是被否决的对象 |
| 大规模实体 | Actor 池 + SoA + HISM | 同上，并把 **Mass Entity** 列为一等评估路径（M0 压测同时评估） | Mass 是 UE5 官方 ECS，比自建 SoA 更可维护 |
| 相机抖动 | 自己写偏移 | `UCameraShakeSourceComponent` + `ULegacyCameraShake`，参数（幅度/时长/频率）按 §07 配置 | 原生、可数据化、可被设置项统一缩放 |

| UI | CommonUI | 保持不变 ✅ | 原决议已是最佳实践 |
| 存档 | `USaveGame` + 三级备份 | 保持不变 ✅，GE 句柄不序列化、读档重建 | 原决议已是最佳实践 |

## 5. 随机数与可复现性（★ 确定性目标降级并明确化）

### 5.1 决议

**不再追求「逐帧确定性」**。旧文档为此付出了固定帧 + 全局单流 RNG 的代价，而项目的真实需求只有三条：

| 真实需求 | 新方案 |
|---|---|
| bug 复现 / Daily Run：同 seed → 同商店、同掉落、同刷怪序列 | **RNG 按用途分流**，每流独立 `FRandomStream` |
| 数值回归测试 | 纯函数核心（`BrotatoCore`）单测 + 固定步长 headless 模拟 |
| 表现层随机（抖动、粒子、音高） | 不要求复现，可用 `FMath::FRand()` |

### 5.2 RNG 分流表

```cpp
enum class EBrotatoRngChannel : uint8
{
    Shop,        // 商店抽取、重掷、Tier 抽取
    Loot,        // 掉落、材料、宝箱
    Spawn,       // 波次刷怪、精英抽取、兽潮
    Combat,      // 暴击、闪避、燃烧点燃、吸血
    Cosmetic,    // ★ 纯表现：屏震、音高、粒子（不参与复现）
    Count
};
// UBrotatoRunSubsystem 持有 Count 个流，全部由 RunSeed 派生：
// Streams[i].Initialize(HashCombine(RunSeed, (int32)i));
```

- **Shop / Loot / Spawn 三流与帧率无关**（调用点是离散事件，不在 Tick 里），因此在可变帧率下依然严格可复现。
- **Combat 流**与命中顺序相关，只保证统计分布，不保证逐次复现 —— 这是接受可变帧率的代价，且不影响任何玩法验收项。
- 原作两种判定的**比较符差异必须保留**（影响期望值）：`ChanceSuccess` 用 `<=`，`DodgeRoll` 用 `<`。
- ExecCalc / MMC 内**仍禁止** `FMath::FRand()`，必须取对应 Channel 的流。

### 5.3 确定性测试的 UE 原生做法

不再为测试而改变生产架构，改用引擎自带的固定步长模式：

```
UnrealEditor-Cmd.exe <Project> -ExecCmds="Automation RunTests Brotato" \
    -UseFixedTimeStep -FixedDeltaTime=0.0166667 -nullrhi -unattended
```

> `FApp::SetUseFixedTimeStep(true)` + `FApp::SetFixedDeltaTime()` 是 UE 官方用于渲染/回归的确定性手段。**生产运行走可变帧率，回归测试走固定步长**，两者共用同一份代码路径。

## 6. 取整契约的适用边界（收窄，但不废除）

旧文档的 Godot / UE 取整差异表（`BrotatoRound` half-away-from-zero、`BrotatoTruncInt` 截断向零）**继续有效**，因为它影响**数值结果**，属于 What。但适用范围收窄：

| 类别 | 是否取整 | 说明 |
|---|---|---|
| 伤害、HP、护甲、材料、金币、XP、等级、数量、价格 | ✅ 走 `BrotatoRound` / `BrotatoTruncInt` / `FloorToInt` / `CeilToInt` | 保持与原作逐值一致 |
| **时间、冷却、时长、间隔** | ❌ **不取整** | 全程 float 秒。旧文档「冷却抖动结果必须截断向零」「攻速冷却 `as int`」等条目**作废** |
| 距离、速度、角度、缩放、透明度 | ❌ 不取整 | float |

> 因此旧风险清单中的 **#14「冷却抖动取整」** 与 **§09 §2.5 中 §04 §7.4 / §04 §4.10 两行**予以删除；其余取整条目全部保留。
> 冷却秒化后的等价式见 §04 §7.4（已改写）：抖动上下限以秒比较，下限 `FMath::Max(1.f/60.f, CD - R)`，结果**不取整**。

| Cue Proxy ASC | 无主 Cue 播放无原生方案 | 永久 |
| 2D 空间哈希 | **仅当** UE 碰撞查询在 200 单位 + 500 子弹压测下超出 2 ms 预算 | M0 压测结论触发 |
