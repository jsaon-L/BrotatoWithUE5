# 09 · UE5 实现架构与数据表（分级 GAS 方案）

> 目标引擎：**Unreal Engine 5.8**
> **双重目标**：① 规则/数值/手感还原 Brotato；② 借此项目**系统性掌握 GAS（Gameplay Ability System）**
> **本章覆盖并取代** §02 §10、§08 §7 中关于属性/效果系统的实现建议。数值公式仍以 §02–§07 为准。
> ★ **实现方式以 [00_UE化移植准则与时间基规范](00_UE化移植准则与时间基规范.md) 为最高仲裁**：全工程时间基为**秒**、模拟走**可变 `DeltaTime` + 固定阶段顺序**、GAS 的 Duration/Periodic/Cooldown GE **全部启用**。本章已按 v2.0 改写。

## 0. 核心架构决策：Tiered GAS（分级 GAS）

### 0.1 矛盾与解法

| 矛盾 | 说明 |
|---|---|
| 想学 GAS | GAS 是 UE 最值得掌握的 Gameplay 框架，但它是"重"框架 |
| 肉鸽有 100–144 同屏敌人 | 每个 ASC ≈ 数 KB + Aggregator 字典 + Tag 容器 + 委托，全量铺开必崩 |
| 数值必须 1:1 | GAS 的 Aggregator 有自己的运算顺序，必须先验证语义能否精确映射 |

**解法：按实体重要性分级，只在"值得"的地方付 GAS 的代价。**

```
┌─ Tier A · 完整 GAS ────────────────────────────────────────┐
│  玩家（1 个）                                               │
│  ASC + 4 个 AttributeSet + Infinite/Duration/Instant GE     │
│  + GameplayAbility（武器攻击）+ AbilityTask（挥击时序）      │
│  + GameplayCue（受击/治疗/升级）+ GameplayTag 状态机         │
│  → 练：AttributeSet、MMC、ExecCalc、Stacking、Cue、Ability   │
└─────────────────────────────────────────────────────────────┘
┌─ Tier B · 轻量 GAS（可选开关）────────────────────────────┐
│  Boss + 精英（同屏 ≤ 4 个）                                 │
│  精简 ASC + 1 个 AttributeSet                               │
│  + Duration / Periodic GE 承载燃烧/减速/减益的属性修正与计时      │
│    （★ 计时由 GAS 原生驱动，见 §2.2）                        │
│  + GameplayTag 驱动阶段状态机                                │
│  → 练：GE 动态增删、Tag 事件、GE 批量移除、Stacking          │
└─────────────────────────────────────────────────────────────┘
┌─ Tier C · 无 ASC 纯数据 ──────────────────────────────────┐
│  普通敌人（100–144）、树、结构物（炮塔/地雷/花园）           │
│  FEnemyState（SoA 数组）+ 共享 FBrotatoDamageMath 计算核心   │
│  状态效果用固定 slot（燃烧 1 + 减速 1，原作本就不叠层）      │
└─────────────────────────────────────────────────────────────┘
┌─ Tier D · 无 Actor ───────────────────────────────────────┐
│  子弹（500）、材料（50）、飘字（100）、特效（100）           │
│  结构体数组 + 批量更新 + HISM/Niagara 批渲染                 │
└─────────────────────────────────────────────────────────────┘
```

### 0.2 ★ 第一原则：计算核心非 GAS，GAS 只做"编排"

这是让上述分级不发散的唯一办法：

```
                    ┌──────────────────────────────┐
                    │  FBrotatoDamageMath (纯静态) │  ← 唯一真源，可单测
                    │  ArmorCoef / Crit / Dodge    │     不依赖任何 UE Gameplay 类型
                    │  HpRegenTimer / EndlessFactor│
                    └───────────┬──────────────────┘
                    ┌───────────┴───────────┐
       ┌────────────▼───────────┐  ┌────────▼─────────────┐
       │ UBrotatoDamageExecCalc │  │ FBrotatoDamagePipeline│
       │ (GAS ExecutionCalc)    │  │ (纯函数, 敌人用)      │
       │ Tier A / B 走这里       │  │ Tier C 走这里          │
       └────────────────────────┘  └──────────────────────┘
```

**规则**：
1. 任何公式**只允许写一次**，放在 `FBrotatoDamageMath`
2. ExecCalc 与 Pipeline 都只做「捕获数据 → 调 Math → 写回结果」
3. 单元测试**同时跑两条路径**，断言结果完全一致（见 §12.3）

同理适用于武器开火：`FWeaponFireCore`（非 GAS）被玩家的 `UGA_WeaponAttack` 与结构物的 `ATurret` 共同调用。

## 2. 时间基、模拟编排与确定性

### 2.1 ★ 秒制时间基与 `UBrotatoSimSubsystem`

原作以 60 Hz 物理帧计时（`cooldown=60` 即 1 s），那是 Godot 的实现方式，**不是复刻目标**。本项目：

- **时间量唯一单位是秒（float）**，导入期即完成 `秒 = 帧/60` 换算，运行时/数据表中**不存在帧字段**；
- **不使用固定步长逻辑帧**，改为 UE 标准可变 `DeltaTime`；一致性由**固定的阶段顺序**（§2.4）保证，而非固定的时间步长；
- 所有随时间变化的量**必须乘 `DeltaTime`**，指数衰减用半衰期式（`Rate = -60·ln(k)`）。

```cpp
UCLASS()
class UBrotatoSimSubsystem : public UWorldSubsystem, public FTickableGameObject
{
    GENERATED_BODY()
public:
    virtual void Tick(float DeltaTime) override
    {
        if (bPaused) return;
        // ★ 固定的阶段顺序（§2.4），每一步都吃真实 DeltaTime
        StepWave(DeltaTime);
        StepSpawnQueues(DeltaTime);
        StepMovement(DeltaTime);
        StepWeapons(DeltaTime);
        StepProjectiles(DeltaTime);
        StepCollisionAndDamage(DeltaTime);
        StepPickups(DeltaTime);
        FlushDirtyStats();          // 属性脏标记合批（每 Tick 最多一次）
        StepCleanup();
        SubmitPresentation(DeltaTime);
    }
    virtual TStatId GetStatId() const override { RETURN_QUICK_DECLARE_CYCLE_STAT(BrotatoSim, STATGROUP_Tickables); }

    double GetRunTimeSeconds() const { return RunTime; }   // ★ double，避免长局累加漂移

private:
    double RunTime = 0.0;
    bool   bPaused = false;
};
```

> 原作 `Utils.physics_one(delta) = physics_fps × delta`（60 Hz 下恒为 1）的所有用法，等价改写为 `X -= DeltaTime`（X 为秒）。

**按秒节流替代按帧计数**（原作的「每 3 帧 / 每 60 帧」）：

```cpp
Accum += DeltaTime;
while (Accum >= Interval) { Accum -= Interval; DoOnce(); }   // 例：Interval = 0.05f（20 次/s）
```

### 2.2 ★ GAS 原生计时（旧版禁令已作废）

**决议：ASC 保持引擎默认 Tick，Duration / Periodic / Cooldown GE 全部启用。** 旧版「关闭 ASC Tick 并由固定帧手动驱动」的方案已删除 —— 它与 GAS 的生命周期、预测、Cue 播放全部冲突，且会失去 Pause/TimeDilation 的自动正确性。

| GE 类型 | 用途 | 计时归属 |
|---|---|---|
| **Instant** | 伤害、治疗、升级永久属性 | 无计时 |
| **Infinite** | 物品/角色/套装/难度/常驻被动 | 无计时（显式 Remove） |
| **Duration** | **无敌窗口、吸血 CD、临时 Buff、减速** | ✅ GAS 原生（World 时间） |
| **Periodic** | **燃烧 tick、生命回复、`lose_hp_per_second`、每 5 s 临时属性叠加** | ✅ GAS 原生 |
| **Cooldown** | **武器攻击冷却、结构物开火冷却** | ✅ GAS 原生（见 §9.3） |

**运行时决定时长/周期的标准手法**：

```cpp
// 时长：GE 的 Duration Policy = HasDuration，Duration Magnitude = SetByCaller
Spec->SetSetByCallerMagnitude(BrotatoTags::Data_Duration, DurationSeconds);

// 周期：Period 是 FScalableFloat（不支持 SetByCaller），但 Spec 上可直接改写
Spec->Period = BurnTickIntervalSeconds;   // 燃烧缩减档位无需拆成多个 GE 资产
```

**状态计时映射（取代全部 `int32 *FramesLeft` 字段）**：

| 机制 | 实现 |
|---|---|
| 无敌窗口 0.4 / 0.3 / 0.2 s | Duration GE 授予 `State.Invincible`；`GE_Damage` 的 `ApplicationTagRequirements.IgnoreTags` 直接拦截 → **伤害公式内无需任何无敌分支** |
| 吸血 CD 0.1 s | Duration GE 授予 `State.LifestealCd`，同样用 Tag 需求拦截 |
| 燃烧 N tick × 间隔 T | Periodic GE：`Period = T`、`Duration = N × T`；`StackDurationRefreshPolicy` 表达「刷新不叠层」 |
| 生命回复 / 每秒掉血 | Periodic GE（`Period = 1`），Magnitude 走 MMC 读当前属性 |
| 每 5 s 临时属性叠加 | Periodic GE（`Period = 5`）+ `StackingType = AggregateBySource` + `StackLimitCount` |
| 受击闪白 0.1 s | Timed GameplayCue 或 `UMaterialInstanceDynamic` + Timer |

> 这样既保住正确性与可维护性，又让 GAS 的核心能力（AttributeSet / Modifier / MMC / ExecCalc / Stacking / Cue / Tag / Cooldown）**全部被真正练到** —— 旧方案把 Periodic/Duration 禁掉，等于把 GAS 一半的内容排除在学习目标之外。

### 2.3 随机数（按用途分流）

```cpp
enum class EBrotatoRngChannel : uint8 { Shop, Loot, Spawn, Combat, Cosmetic, Count };

class FBrotatoRandom
{
    FRandomStream Stream;
public:
    void Seed(int32 InSeed) { Stream.Initialize(InSeed); }
    float Rand()  { return Stream.FRand(); }                 // [0, 1)
    float RandRange(float A, float B);
    int32 RandInt(int32 A, int32 B);
    template<typename T> const T& RandElement(const TArray<T>&);

    // ★ 严格对齐原作的两种判定（比较符不同，影响期望值！）
    bool ChanceSuccess(float Chance)  // Utils.get_chance_success
    { return Chance != 0.f && Stream.FRand() <= Chance; }     // <=
    bool DodgeRoll(float Chance)
    { return Stream.FRand() < Chance; }                        // <
};

// UBrotatoRunSubsystem 持有 Count 个流，全部由 RunSeed 派生：
//   Streams[i].Initialize(HashCombine(RunSeed, (int32)i));
```

**GAS 侧注意**：ExecCalc / MMC 里**禁止使用 `FMath::FRand()`**，必须取 `UBrotatoRunSubsystem::GetRandom(EBrotatoRngChannel::Combat)`。

> **★ 确定性口径（v2.0 修订）**：本项目**不追求逐帧确定性**。
> - **Shop / Loot / Spawn** 三流的调用点都是离散事件（开店、掉落、刷怪组触发），与帧率无关 → **同 seed 严格可复现**，足以支撑 bug 复现与 Daily Run；
> - **Combat** 流与命中顺序相关，只保证统计分布一致；
> - **Cosmetic** 流（屏震/音高/粒子）不参与复现；
> - 回归测试用引擎原生固定步长：`-UseFixedTimeStep -FixedDeltaTime=0.0166667 -nullrhi`（详见 §00 §5.3）。
> - `FRandomStream` 算法与 Godot RNG 不同，**无法与原版录像逐帧复现**；§15.4 的"黄金基线"仅指本工程自己的历史快照。

### 2.5 ★ 整数与舍入契约（必读）

Godot 与 UE 的取整语义**不同**，这是数值复刻最隐蔽的偏差源。所有涉及 `round()` / `as int` / `int()` / `floor()` 的地方必须走下面的封装函数，**禁止直接用 `FMath::RoundToInt`**。

> ★ **适用边界（§00 §6）**：本节只适用于**整数语义量**（伤害、HP、护甲、材料、金币、XP、等级、数量、价格）。
> **时间、冷却、时长、间隔、距离、速度、角度全程 float，不取整** —— 旧版「冷却抖动结果截断向零」「攻速冷却 `as int`」两条已作废。

| 语义 | Godot | UE 默认 | 是否一致 | 本项目封装 |
|---|---|---|---|---|
| 四舍五入 | `round(x)`：**half away from zero**<br>`round(0.5)=1`、`round(-0.5)=-1`、`round(2.5)=3`、`round(-2.5)=-3` | `FMath::RoundToInt(x)`：**half to +∞**<br>`(0.5)=1`、`(-0.5)=0`、`(2.5)=3`、`(-2.5)=-2` | ❌ **负半整数处分叉** | `BrotatoRound()` |
| 浮点→整数 | `int(x)` / `as int`：**截断向零**<br>`int(1.9)=1`、`int(-1.9)=-1` | `FMath::TruncToInt(x)`：同为截断向零 | ✅ | `BrotatoTruncInt()` |
| 向下取整 | `floor(x)` | `FMath::FloorToInt(x)` | ✅ | 直接用 `FloorToInt` |
| 向上取整 | `ceil(x)` | `FMath::CeilToInt(x)` | ✅ | 直接用 `CeilToInt` |

```cpp
namespace BrotatoMathInt
{
    /** 对齐 Godot round()：half away from zero */
    FORCEINLINE int32 BrotatoRound(float X)
    {
        return X >= 0.f ? FMath::FloorToInt(X + 0.5f)
                        : -FMath::FloorToInt(-X + 0.5f);
    }
    FORCEINLINE int64 BrotatoRound64(double X) { /* 同上 */ }

    /** 对齐 Godot `as int` / int()：截断向零 */
    FORCEINLINE int32 BrotatoTruncInt(float X) { return FMath::TruncToInt(X); }
}
```

**必须使用 `BrotatoRound()` 的位置**（都可能出现负值）：

| 位置 | 表达式 | 为何可能为负 |
|---|---|---|
| §02 §5.1 步骤 7 | `round(damage × (pct + exp))` | Renegade 的 `DMG% = -400` → 乘区 = −3 |
| §02 §5.2 暴击 | `round(value × crit_damage)` | 同上（原始伤害已可为负） |
| §02 §4.3 玩家护甲 | `round(dmg × armor_coef)` | 负护甲 → 系数 > 1，但 dmg 可能为负 |
| §02 §9 `percent_materials` | `val = (pct/100) × gold` | Streamer 的负向条目 |
| §06 §8.1 敌人属性 | `round(base × (Acc + S))` | `enemy_health` 等可被角色调负 |
| §02 §8 属性转换 | `Δ` 计算 | 转出为负 |

**必须使用 `BrotatoTruncInt()` 的位置**：

| 位置 | 表达式 |
|---|---|
| §05 §3.5 定价 / §3.6 重掷 / §3.9 回收 | `... as int`（值恒正，等价 floor，但仍用统一封装） |
| §06 §3 无尽 | `int((index / 10.0) * 2)`、`int(100 × (1.25 + i×0.01))` |
| §06 §5.3 刷怪数 | `int(1 + bonus_enemies_per_group)` |
| §02 §4.1 最大生命 | `clamp(...) as int` |

**必须使用 `FloorToInt()` 的位置**：`LinkedStats` 的 `floor(scaled / nb)`（§4.5）、`Tier` 期望取整的整数部分（§06 §5.3 中立单位）。

**必须使用 `CeilToInt()` 的位置**：收获自增长 `ceil(0.05H)` / `ceil(0.20H)`（§02 §4.7）、HP 商店价格 `ceil(value/20)`（§05 §3.10）、无尽附加精英数 `ceil((W-20)/10)`（§06 §3）、波次计时显示 `ceil(time_left)`（§08 §3.1）。

> **单测**：见 §02 §10.3 的 T13 / T14，以及 §15.1 的 `IntSemanticsTest.cpp`。
> **Editor 校验**：在 `BrotatoEditor` 加一条静态检查，扫描 `Source/` 下对 `FMath::RoundToInt` 的直接调用并告警（只允许出现在 `BrotatoMathInt` 内部）。

### 2.4 模拟阶段顺序（★ 固定不可变）

顺序固定，但每阶段吃真实 `DeltaTime`（不是 1/60）：

```
S1.  输入采样（EnhancedInput）
S2.  WaveManager 推进           波次计时（秒）→ 刷怪组触发
S3.  EntitySpawner 分摊生成      按秒节流：5 条队列，每队列 20 个/s（原作"每 3 帧 1 个"）
S4.  移动行为求解 → 期望速度合成
S5.  位移与碰撞解算（SafeMoveUpdatedComponent / 批量 Overlap）
S6.  击退与外力衰减              Velocity *= Exp(-6.3216 * DeltaTime)（原作每帧 ×0.9）
S7.  武器
      7a. 选靶 + 开火判定（冷却状态由 Cooldown GE 的 Tag 查询，见 §9.3）
      7b. Tier A: TryActivateAbility(GA_WeaponAttack)
          Tier C: FWeaponFireCore::Fire()
      7c. 挥击 Tween 推进（UAbilityTask，按秒 + UCurveFloat）
S8.  投射物批更新（含 LaunchDelay 0.02 s 累减）
S9.  命中判定 → 伤害结算
      9a. 目标是玩家/Boss → ApplyGameplayEffectToTarget(GE_Damage)
          （无敌/吸血 CD 由 GE 的 ApplicationTagRequirements 拦截）
      9b. 目标是普通敌人 → FBrotatoDamagePipeline::Apply()
S10. 拾取物吸附与结算
S11. ★ 属性脏标记统一处理（每 Tick 最多一次）：
      11a. LinkedStats GE 重算（见 §4.5）
      11b. 武器 RuntimeStats 重算
      11c. 广播 UI
S12. 死亡清理 + 对象回收
S13. 表现层提交（Cue / 飘字 / 屏震 / 音效）
```

**与旧版「16 步逻辑帧」的差异**：
- 删除「冷却帧计数递减」 → Cooldown GE（§9.3）
- 删除「状态效果帧推进」 → Periodic / Duration GE（§2.2）
- 删除「`ASC.FixedTickASC()`」 → ASC 恢复引擎默认 Tick
- 「结构物生成检查（每 60 帧）」 → 1 s 循环 Timer 或 Periodic GE
- 所有「每 N 帧」计数节流 → 按秒累加器节流

## 4. ★ 属性系统：Brotato 三层 → GAS Aggregator 的精确映射

### 4.1 原作模型回顾

$$\text{FinalStat}(s) = \Big(\underbrace{E[s]}_{\text{永久}} + \underbrace{T[s]}_{\text{波内}} + \underbrace{L[s]}_{\text{联动}}\Big)\cdot\Big(1 + \frac{E[\text{gain\_}s]}{100}\Big)$$

### 4.2 GAS Aggregator 公式

```
CurrentValue = ((BaseValue + Σ Additive) × Π Multiplicative) / Π Division
然后 Override（若存在）直接覆盖结果
```

### 4.3 ★ 映射方案（完美对应，无需妥协）

| Brotato 概念 | GAS 实现 | 说明 |
|---|---|---|
| `stat_max_hp` 初始 10，其余初始 0 | **BaseValue** | AttributeSet 构造函数里设 |
| 永久层 `E[s]`（物品/角色/套装/难度） | **Infinite GE，`EGameplayModOp::Additive`** | 可移除（卖物品/卸下套装） |
| 升级（永久且不可撤销） | **Instant GE，Additive** | 直接改 BaseValue，省 Aggregator 条目 |
| 波内层 `T[s]` | **Infinite GE + Tag `Effect.Lifetime.Wave`** | 波末 `RemoveActiveEffectsWithTags` 一键清空 |
| 联动层 `L[s]` | **Infinite GE + Tag `Effect.Lifetime.Linked`** | 脏时移除重建（见 §4.5） |
| `gain_xxx` 乘区 | **Infinite GE，`Multiplicative`，AttributeBased 非快照** | 见 §4.4 —— 这是最漂亮的一处 |
| `hp_cap` / `dodge_cap` / `speed_cap` / `weapon_slot`（REPLACE 语义） | **Infinite GE，`EGameplayModOp::Override`** | Ghost 90 / Cryptid 70 不会共存，无冲突 |

> **结论：GAS 的 `(Base + Add) × Mul` 与 Brotato 的 `(三层相加) × (1+gain/100)` 数学上完全等价。** 原先"语义不符"的判断是错的 —— 只要把 gain 做成 Multiplicative 就精确吻合。

### 4.4 ★ gain 乘区的实现（AttributeBased 非快照 Modifier）

**做法**：把 16 个 `gain_*` 本身也做成 Attribute，然后主属性挂一条 Multiplicative Modifier，用 `AttributeBased` 捕获对应的 Gain Attribute。

```cpp
// UBrotatoGainAttributeSet
ATTRIBUTE_ACCESSORS(UBrotatoGainAttributeSet, GainMaxHp)
ATTRIBUTE_ACCESSORS(UBrotatoGainAttributeSet, GainSpeed)
// ... 共 16 + 4 个（另含 gain_explosion_damage / piercing_damage / bounce_damage / damage_against_bosses）
```

`GE_StatGainMultipliers`（Infinite，开局即 Apply 且永不移除）配置 20 条 Modifier：

```
Modifier[i]:
  Attribute            = Primary.Speed
  ModifierOp           = Multiplicative
  Magnitude Type       = AttributeBased
    ├─ Backing Attribute  = GainSpeed
    ├─ Attribute Source   = Target
    ├─ Snapshot           = false        ★ 必须 false，才能响应 gain 变化自动重算
    ├─ Coefficient        = 0.01
    ├─ PreMultiplyAdditiveValue  = 100
    └─ PostMultiplyAdditiveValue = 0
  → 结果 = (GainSpeed + 100) × 0.01 = 1 + GainSpeed/100     ✅
```

**这一条配置就完整复刻了 `gain_*` 机制**，且当物品修改 `GainSpeed` 时，`Speed` 的 CurrentValue 会由 GAS 自动重算（非快照 AttributeBased 会注册依赖）。

> **验证要点**：`GainSpeed = -100`（Mage/Chunky 的 `gain_stat_speed -100`）→ 乘区 = 0 → Speed 归零。GAS 的 Multiplicative 允许 0，行为正确。

### 4.5 ★ LinkedStats：GAS 的"属性依赖属性"难题

Brotato 有 20+ 个"每 N 点 X 获得 Y"效果（Chunky、Generalist、Knight、Speedy、Hunter…）。这是 GAS 的经典坑。

**难点**：
1. `L[s]` 依赖其他属性的当前值 → 需要动态重算
2. **存在循环依赖**：Generalist「每 1 远程 → +2 近战」且「每 2 近战 → +1 远程」
3. 原作用**整数除法 + 单次快照计算**天然避免震荡

#### 方案对比

| 方案 | 做法 | 问题 |
|---|---|---|
| A. 自定义 MMC（快照） | `UMMC_LinkedStat` 捕获源属性 | Infinite GE 只在 Apply 时算一次，后续不更新 ❌ |
| B. MMC 非快照 | 设 `bSnapshot = false` | **会触发递归重算 → 循环依赖直接死循环** ❌ |
| C. **移除 + 重建（推荐）** | 脏标记 → Tick 末（阶段 S11a）移除旧 GE → 单次快照计算 → Apply 新 GE | ✅ 与原作行为完全一致 |

#### 方案 C 实现

```cpp
UCLASS()
class UBrotatoLinkedStatsComponent : public UActorComponent
{
public:
    void MarkDirty() { bDirty = true; }

    /** 在模拟阶段 S11a 调用，每 Tick 最多执行一次 */
    void FlushIfDirty()
    {
        if (!bDirty) return;
        bDirty = false;

        // 1. 移除旧的 Linked GE（★ 先移除，保证下面读到的是"不含 Linked"的值）
        FGameplayTagContainer LinkedTag(BrotatoTags::Effect_Lifetime_Linked);
        ASC->RemoveActiveEffectsWithGrantedTags(LinkedTag);

        // 2. ★ 单次快照计算：所有 Link 读同一时刻的属性值，不迭代、不递归
        FGameplayEffectSpecHandle Spec = ASC->MakeOutgoingSpec(GE_LinkedStats, 1.f, Ctx);
        for (const FBrotatoHookEntry& Link : HookRegistry->Get(BrotatoTags::Hook_StatLinks))
        {
            const float Scaled = ResolveScaleSource(Link.ExtraName, Link.bPermOnly);
            const int32 Chunks = FMath::FloorToInt(Scaled / Link.ExtraA);   // ★ 整数除法
            Spec.Data->SetSetByCallerMagnitude(Link.Key, Link.Value * Chunks);
        }
        ASC->ApplyGameplayEffectSpecToSelf(*Spec.Data);
    }

private:
    /** 对应原作 8 种缩放源 */
    float ResolveScaleSource(FName Source, bool bPermOnly) const;
    // "materials"      → RunSubsystem->Gold
    // "structure"      → HookRegistry->Get(Structures).Num()
    // "living_enemy"   → EnemySubsystem->GetLivingCount()
    // "living_tree"    → EnemySubsystem->GetLivingTreeCount()
    // "common_item"    → RunSubsystem->CountDistinctItemsOfTier(Common)
    // "legendary_item" → ...(Legendary)
    // "item_xxx"       → RunSubsystem->CountItem(Source)
    // 其他             → bPermOnly ? 只读 Permanent 层 : 读 Permanent+Temp（★ 不含 Linked）

    bool bDirty = false;
};
```

**`GE_LinkedStats` 配置**：Infinite，`GrantedTags += Effect.Lifetime.Linked`，包含全部可能被链接的属性各一条 `Additive` + `SetByCaller` Modifier（SetByCaller 未设置时默认 0，需勾选 `bAllowNonExistentSetByCaller`）。

**`ResolveScaleSource` 的关键约束**：
> 读源属性时**必须排除 Linked 层本身**（`Permanent + Temp`，不含 `Linked`）。
> 这与原作 `perm_only ? RunData.get_stat(s) : RunData.get_stat(s) + TempStats.get_stat(s)` 完全一致 —— 原作也从不把 LinkedStats 计入源。这是避免循环依赖的根本机制。
>
> GAS 实现上：因为我们在第 1 步已经**先移除了 Linked GE**，此时 `GetNumericAttribute()` 读到的天然就是 `Permanent + Temp`。✅

**触发 MarkDirty 的时机**：`AddItem` / `RemoveItem` / `AddWeapon` / `RemoveWeapon` / `AddGold`（仅当存在 materials 链）/ 升级完成 / 波末结算 / 结构物增减。

### 4.7 Clamp 处理

```cpp
void UBrotatoCoreAttributeSet::PreAttributeChange(const FGameplayAttribute& Attr, float& NewValue)
{
    Super::PreAttributeChange(Attr, NewValue);

    if (Attr == GetMaxHpAttribute())
    {
        // clamp(stat_max_hp, 1, hp_cap)
        const float Cap = GetOwningAbilitySystemComponent()
            ->GetNumericAttribute(UBrotatoLimitAttributeSet::GetHpCapAttribute());
        NewValue = FMath::Clamp(NewValue, 1.f, Cap);
    }
    else if (Attr == GetHealthAttribute())
    {
        NewValue = FMath::Clamp(NewValue, 0.f, GetMaxHp());
    }
    else if (Attr == GetDodgeAttribute())
    {
        // 属性侧 clamp（判定侧还有第二道，见 §02 §4.4 的"双重 clamp"）
        const float Cap = /* DodgeCap */;
        NewValue = FMath::Min(NewValue, Cap);
    }
    else if (Attr == GetSpeedAttribute())
    {
        NewValue = FMath::Min(NewValue, /* SpeedCap */);
    }
}
```

> ⚠️ `PreAttributeChange` 只 clamp **CurrentValue**，不改 BaseValue。`MaxHp` 变小时需要在 `PostGameplayEffectExecute` 里同步 clamp `Health`。

### 5.3 运行时应用（★ 句柄管理，修复原作 bug）

```cpp
USTRUCT()
struct FBrotatoAppliedEffects
{
    TArray<FActiveGameplayEffectHandle>  GEHandles;      // GE 句柄
    TArray<FGuid>                        HookIds;        // HookRegistry 条目 ID
    TArray<FGameplayAbilitySpecHandle>   AbilityHandles; // Passive Ability
    TArray<FGameplayTag>                 LooseTags;      // Rule.* 开关
};

// UBrotatoRunSubsystem
TMap<FObjectKey /*ItemInstance*/, FBrotatoAppliedEffects> AppliedMap;

void UBrotatoRunSubsystem::AddItem(UBrotatoItemData* Item)
{
    FBrotatoAppliedEffects& Applied = AppliedMap.Add(FObjectKey(Item));

    // 1. 把该物品的所有 StatModifier 类 Effect 合成 ★一个 GE Spec★
    if (FGameplayEffectSpecHandle Spec = BuildStatSpec(Item, Applied))
        Applied.GEHandles.Add(ASC->ApplyGameplayEffectSpecToSelf(*Spec.Data));

    // 2. 钩子类写入 Registry，记录 GUID
    for (const FBrotatoEffectDef& Def : Item->Effects)
        if (IsHookKind(Def.Kind))
            Applied.HookIds.Add(HookRegistry->Add(Def, Item));

    // 3. Rule 开关
    for (FGameplayTag RuleTag : Item->GetRuleTags())
    {
        ASC->AddLooseGameplayTag(RuleTag);
        Applied.LooseTags.Add(RuleTag);
    }

    // 4. Passive Ability
    for (const FBrotatoEffectDef& Def : Item->Effects)
        if (Def.GrantedPassive)
            Applied.AbilityHandles.Add(ASC->GiveAbilityAndActivateOnce(
                FGameplayAbilitySpec(Def.GrantedPassive, 1, INDEX_NONE, Item)));

    UpdateItemRelatedEffects();      // 四步幂等重算，见 §5.4
    LinkedStats->MarkDirty();
}

void UBrotatoRunSubsystem::RemoveItem(UBrotatoItemData* Item)
{
    FBrotatoAppliedEffects Applied;
    if (!AppliedMap.RemoveAndCopyValue(FObjectKey(Item), Applied)) return;

    for (auto H : Applied.GEHandles)      ASC->RemoveActiveGameplayEffect(H);
    for (auto Id : Applied.HookIds)       HookRegistry->Remove(Id);   // ★ GUID 精确移除
    for (auto H : Applied.AbilityHandles) ASC->ClearAbility(H);
    for (auto T : Applied.LooseTags)      ASC->RemoveLooseGameplayTag(T);

    UpdateItemRelatedEffects();
    LinkedStats->MarkDirty();
}
```

> **★ 修复原作 bug**：原作 `Array.erase([key, value])` 靠值比较，同一物品叠 3 份时移除会错删。这里用 **`FActiveGameplayEffectHandle` + `FGuid`**，精确对应。
>
> **★ 性能要点**：把一个物品的所有属性 Modifier 合成**一个** GE Spec（而不是每条 Effect 一个 GE），能把 Aggregator 条目数从 ~600 降到 ~60。

### 5.4 四步幂等重算（`update_item_related_effects`）

原作的 4 类"条件加成"（依赖武器列表），顺序固定：

```cpp
void UBrotatoRunSubsystem::UpdateItemRelatedEffects()
{
    // 每类都是「移除旧 GE → 按当前武器重算 → Apply 新 GE」
    RebuildConditionalGE(EConditional::UniqueWeapon,     GetUniqueWeaponIdCount());
    RebuildConditionalGE(EConditional::AdditionalWeapon, Weapons.Num());
    RebuildConditionalGE(EConditional::TierIVWeapon,     CountWeaponsOfTier(Legendary));
    RebuildConditionalGE(EConditional::TierIWeapon,      CountWeaponsOfTier(Common));
    RebuildSetBonusGE();      // 15 职业套装，见下
}

void UBrotatoRunSubsystem::RebuildSetBonusGE()
{
    // 1. 移除全部套装 GE
    ASC->RemoveActiveEffectsWithGrantedTags(FGameplayTagContainer(BrotatoTags::Effect_Source_Set));

    // 2. 统计件数
    TMap<FGameplayTag, int32> SetCounts;
    for (const FRuntimeWeapon& W : Weapons)
        for (const UBrotatoSetData* S : W.Data->Sets)
            SetCounts.FindOrAdd(S->SetTag)++;

    // 3. ★ 只取当前件数对应的那一档（不叠加）
    for (const auto& KV : SetCounts)
    {
        if (KV.Value < 2) continue;
        const int32 Idx = FMath::Min(KV.Value - 2, 4);     // 2件=档0 … 6件=档4
        const UBrotatoSetData* Set = SetRegistry->Find(KV.Key);
        ApplyEffectDefs(Set->Bonuses[Idx], BrotatoTags::Effect_Source_Set);
    }
}
```

### 5.5 各 Effect 的 GE 配置速查

| Brotato Effect | GE 配置 | 备注 |
|---|---|---|

## 7. 伤害管道（★ 双路径共享核心）

### 7.1 计算核心（`BrotatoCore`，零依赖）

```cpp
namespace FBrotatoDamageMath
{
    /** 玩家护甲：乘法减伤 */
    inline float ArmorCoefMultiplicative(float Armor)
    {
        const float P = 10.f / (10.f + FMath::Abs(Armor) / 1.5f);
        return Armor < 0.f ? (2.f - P) : P;
    }

    /** 玩家侧取值 */
    inline int32 PlayerDmgValue(float Raw, float Armor, bool bArmorApplied)
    {
        return bArmorApplied
            ? FMath::Max(1, FMath::RoundToInt(Raw * ArmorCoefMultiplicative(Armor)))
            : FMath::RoundToInt(Raw);
    }

    /** 敌人侧取值：固定减法 */
    inline int32 EnemyDmgValue(float Raw, float Armor, bool bArmorApplied)
    {
        return bArmorApplied ? FMath::Max(1, FMath::RoundToInt(Raw - Armor))
                             : FMath::RoundToInt(Raw);
    }

    struct FResolveParams
    {
        float Raw = 0.f;
        float Armor = 0.f;
        float Dodge = 0.f, DodgeCap = 60.f;
        float CritChance = 0.f, CritDamage = 1.5f;
        int32 HitProtection = 0;
        bool  bDodgeable = true, bArmorApplied = true;
        bool  bIsPlayer = false;
    };
    struct FResolveResult
    {
        int32 Final = 0;
        bool bDodged = false, bProtected = false, bCrit = false;
        int32 HitProtectionLeft = 0;
    };

    /** ★ 唯一的伤害结算实现，两条路径共用 */
    FResolveResult Resolve(const FResolveParams& P, FBrotatoRandom& Rng)
    {
        FResolveResult R;
        auto DmgValue = [&](float V)
        {
            return P.bIsPlayer ? PlayerDmgValue(V, P.Armor, P.bArmorApplied)
                               : EnemyDmgValue (V, P.Armor, P.bArmorApplied);
        };

        R.Final = DmgValue(P.Raw);
        R.HitProtectionLeft = P.HitProtection;

        if (P.bDodgeable && Rng.DodgeRoll(FMath::Min(P.Dodge, P.DodgeCap / 100.f)))
        { R.Final = 0; R.bDodged = true; }
        else if (R.HitProtectionLeft > 0)
        { --R.HitProtectionLeft; R.Final = 0; R.bProtected = true; }

        if (R.Final != 0 && Rng.ChanceSuccess(P.CritChance))
        {
            // ★ 用原始 Raw 重算，不是 Final × CritDamage
            R.Final = DmgValue(FMath::RoundToInt(P.Raw * P.CritDamage));
            R.bCrit = true;
        }
        return R;
    }
}
```

### 7.2 Tier A/B 路径：GAS ExecutionCalculation

```cpp
struct FBrotatoDamageStatics
{
    DECLARE_ATTRIBUTE_CAPTUREDEF(Armor);
    DECLARE_ATTRIBUTE_CAPTUREDEF(Dodge);
    DECLARE_ATTRIBUTE_CAPTUREDEF(Health);
    DECLARE_ATTRIBUTE_CAPTUREDEF(DodgeCap);
    DECLARE_ATTRIBUTE_CAPTUREDEF(IncomingDamage);

    FBrotatoDamageStatics()
    {
        DEFINE_ATTRIBUTE_CAPTUREDEF(UBrotatoCoreAttributeSet,  Armor,          Target, false);
        DEFINE_ATTRIBUTE_CAPTUREDEF(UBrotatoCoreAttributeSet,  Dodge,          Target, false);
        DEFINE_ATTRIBUTE_CAPTUREDEF(UBrotatoCoreAttributeSet,  Health,         Target, false);
        DEFINE_ATTRIBUTE_CAPTUREDEF(UBrotatoLimitAttributeSet, DodgeCap,       Target, false);
        DEFINE_ATTRIBUTE_CAPTUREDEF(UBrotatoCoreAttributeSet,  IncomingDamage, Target, false);
    }
};

void UBrotatoDamageExecCalc::Execute_Implementation(
    const FGameplayEffectCustomExecutionParameters& Exec,
    FGameplayEffectCustomExecutionOutput& Out) const
{
    const FGameplayEffectSpec& Spec = Exec.GetOwningSpec();
    FAggregatorEvaluateParameters EvalParams;
    EvalParams.SourceTags = Spec.CapturedSourceTags.GetAggregatedTags();
    EvalParams.TargetTags = Spec.CapturedTargetTags.GetAggregatedTags();

    // 1. 无敌窗口：★ 首选做法是在 GE_Damage 资产上配 ApplicationTagRequirements.IgnoreTags
    //    = State.Invincible（GE 根本不会进入 ExecCalc）。此处的兜底判定仅用于
    //    bypass_invincibility 语义（如 lose_hp_per_second 必须穿透）。
    if (EvalParams.TargetTags->HasTag(BrotatoTags::State_Invincible)
        && !Spec.DynamicGrantedTags.HasTag(BrotatoTags::Data_BypassInvincibility))
        return;

    // 2. 捕获数据
    FBrotatoDamageMath::FResolveParams P;
    P.Raw        = Spec.GetSetByCallerMagnitude(BrotatoTags::Data_Damage, false, 0.f);
    P.CritChance = Spec.GetSetByCallerMagnitude(BrotatoTags::Data_CritChance, false, 0.f);
    P.CritDamage = Spec.GetSetByCallerMagnitude(BrotatoTags::Data_CritDamage, false, 1.5f);
    Exec.AttemptCalculateCapturedAttributeMagnitude(Statics().ArmorDef,    EvalParams, P.Armor);
    Exec.AttemptCalculateCapturedAttributeMagnitude(Statics().DodgeDef,    EvalParams, P.Dodge);
    Exec.AttemptCalculateCapturedAttributeMagnitude(Statics().DodgeCapDef, EvalParams, P.DodgeCap);
    P.bIsPlayer = true;   // Tier A；Tier B 的 Boss 走 false 分支

    // 3. ★ 调用共享核心（不在这里写公式！）
    auto& Rng = Exec.GetTargetAbilitySystemComponent()->GetWorld()
                    ->GetSubsystem<UBrotatoRunSubsystem>()->GetRandom();
    const auto R = FBrotatoDamageMath::Resolve(P, Rng);

    // 4. 写回
    if (R.Final > 0)
        Out.AddOutputModifier(FGameplayModifierEvaluatedData(
            Statics().HealthProperty, EGameplayModOp::Additive, -R.Final));

    // 5. Cue 参数（伤害数字颜色 / 屏震强度 / 是否闪白）
    Out.AddOutputModifier(...);   // 或用 GameplayEffectContext 自定义字段传给 Cue
}
```

**`GE_Damage` 配置**：Instant，Execution = `UBrotatoDamageExecCalc`，`GameplayCues += Cue.Hit.Normal`。

### 7.3 Tier C 路径：纯函数管道

```cpp
namespace FBrotatoDamagePipeline
{
    void ApplyToEnemy(FEnemyState& E, const FDamageRequest& Req, FBrotatoRandom& Rng)
    {
        FBrotatoDamageMath::FResolveParams P;
        P.Raw = Req.Damage;  P.Armor = E.Armor;
        P.Dodge = 0.f;                                    // 普通敌人 dodge = 0
        P.CritChance = Req.CritChance; P.CritDamage = Req.CritDamage;
        P.bIsPlayer = false;

        // Boss 额外乘区（damage_against_bosses），在 Resolve 之前
        if (E.bIsBoss && Req.DamageAgainstBosses > 0.f)
            P.Raw = int32(P.Raw * (1.f + Req.DamageAgainstBosses / 100.f));

        const auto R = FBrotatoDamageMath::Resolve(P, Rng);

        // 巨人腰带追伤
        int32 Final = R.Final;
        if (R.bCrit && Req.GiantCritDamage > 0.f)
        {
            const float Div = E.bIsBoss ? 1000.f : 100.f;
            const float EF  = FMath::Max(1.f, Req.EndlessFactor * 0.2f);
            Final += int32((E.Health * (Req.GiantCritDamage / Div)) / EF);
        }

        E.Health = FMath::Max(0, E.Health - Final);
        E.KnockbackVector = Req.KnockDir * Req.KnockAmount;
        if (!R.bDodged && !R.bProtected) E.FlashTimeLeft = 0.1f;   // 秒

        // Cue 通过共享 Proxy ASC 播（见 §8）
        FxSubsystem->QueueHitCue(E.Pos, Final, R.bCrit, R.bDodged, Req.EffectScale);
        if (E.Health <= 0) EnemySubsystem->Kill(E, Req);
    }
}
```

## 8. ★ GameplayCue：让 144 个无 ASC 敌人也能用 Cue

**问题**：`ExecuteGameplayCue` 需要 ASC，但 Tier C 敌人没有。
**解法**：World 级 **Cue Proxy ASC** —— 一个隐藏 Actor 持有唯一 ASC，专门负责播放"无主"Cue。这是业界常用技巧。

```cpp
UCLASS()
class ABrotatoCueProxy : public AActor, public IAbilitySystemInterface
{
    UPROPERTY() UAbilitySystemComponent* ASC;
public:
    virtual UAbilitySystemComponent* GetAbilitySystemComponent() const override { return ASC; }

    /** 在任意世界位置播放 Cue，无需目标 ASC */
    void ExecuteCueAtLocation(FGameplayTag CueTag, FVector Loc, FVector Dir, float Magnitude)
    {
        FGameplayCueParameters P;
        P.Location = Loc;
        P.Normal   = Dir;
        P.RawMagnitude = Magnitude;
        P.SourceObject = this;
        ASC->ExecuteGameplayCue(CueTag, P);
    }
};
```

### 8.1 Cue 分工

| Cue | 播放者 | 说明 |
|---|---|---|
| `Cue.Player.Damaged` / `Healed` / `LevelUp` | 玩家 ASC | 屏震 5px + 红色飘字 + 暗角更新 |
| `Cue.Hit.Normal` / `Crit` / `Dodge` / `Nullified` | 玩家 ASC（受击）/ **Proxy ASC**（敌人受击） | 白闪 + 粒子 + 飘字 |
| `Cue.Enemy.Damaged` / `Died` | **Proxy ASC** | |
| `Cue.Weapon.MeleeSwing` / `RangedFire` | 玩家 ASC（Ability 内）/ Proxy（结构物） | 音效 |
| `Cue.Explosion` / `Burning` | Proxy ASC | |

### 8.2 Cue 限流（对齐原作硬上限）

原作有 `MAX_GRAPHICAL_EFFECTS = 100` / `MAX_TEXTS = 100`。**在调用 Cue 之前限流，不要在 CueNotify 内部**（否则 Cue 生命周期管理会乱）：

```cpp
void UFxSubsystem::QueueHitCue(FVector2D Pos, int32 Dmg, bool bCrit, bool bDodge, float EffectScale)
{
    if (!Settings.bVisualEffects) return;
    if (ActiveGraphicalEffects >= 100) return;              // ★ 原作上限
    if (!(Rng.Rand() < EffectScale)) return;                // ★ 原作：randf() < effect_scale（注意括号，别写成 !Rng.Rand() < X）
    CueProxy->ExecuteCueAtLocation(bCrit ? Cue_Hit_Crit : Cue_Hit_Normal, ...);
}
```

### 9.2 `UGA_WeaponAttack`

```cpp
UCLASS()
class UGA_WeaponAttack : public UGameplayAbility
{
public:
    UGA_WeaponAttack()
    {
        InstancingPolicy = EGameplayAbilityInstancingPolicy::InstancedPerActor;
        NetExecutionPolicy = EGameplayAbilityNetExecutionPolicy::ServerOnly;   // 单机
        // ★ 冷却走 GAS 原生 Cooldown GE（见 §9.3）
        CooldownGameplayEffectClass = UGE_WeaponCooldown::StaticClass();
        AbilityTags.AddTag(BrotatoTags::Ability_WeaponAttack_Melee);
        ActivationBlockedTags.AddTag(BrotatoTags::State_Dead);
        ActivationBlockedTags.AddTag(BrotatoTags::State_CleaningUp);
    }

    virtual bool CanActivateAbility(...) const override
    {
        const ABrotatoWeapon* W = Cast<ABrotatoWeapon>(GetCurrentSourceObject());
        if (!W) return false;
        // 冷却由基类的 CheckCooldown() 判定（Cooldown GE 的 Tag），此处不再手写计数器

        // Soldier: can_attack_while_moving == 0
        if (!ASC->HasMatchingGameplayTag(BrotatoTags::Rule_CanAttackWhileMoving)
            && ASC->HasMatchingGameplayTag(BrotatoTags::State_Moving)) return false;

        return FWeaponFireCore::ShouldFire(W->RuntimeStats, W->CurrentTarget, ...);
    }

    virtual void ActivateAbility(...) override
    {
        ABrotatoWeapon* W = Cast<ABrotatoWeapon>(GetCurrentSourceObject());
        W->NbShotsTaken++;

        if (W->IsMelee())
        {
            // ★ AbilityTask 驱动挥击时序（THRUST / SWEEP），按秒 + UCurveFloat
            auto* Task = UAbilityTask_MeleeSwing::Create(this, W);
            Task->OnHitboxEnable.AddDynamic(this, &ThisClass::OnHitboxEnable);
            Task->OnFinished.AddDynamic(this, &ThisClass::OnSwingFinished);
            Task->ReadyForActivation();
        }
        else
        {
            // 远程：同一 Tick 生成全部子弹（原作无时间 burst）+ 后坐动画
            FWeaponFireCore::SpawnProjectiles(W, ProjectileSubsystem);
            K2_ExecuteGameplayCue(BrotatoTags::Cue_Weapon_RangedFire);
            auto* Task = UAbilityTask_WaitDelay::WaitDelay(this, W->RuntimeStats.RecoilDuration * 2.f);
            Task->OnFinish.AddDynamic(this, &ThisClass::OnSwingFinished);
            Task->ReadyForActivation();
        }
        // ★ 冷却在攻击序列结束（OnSwingFinished）时 ApplyCooldown()，
        //   等价于原作「射击期间冷却不递减」，见 §9.3
    }

    void OnSwingFinished()
    {
        ApplyCooldown(CurrentSpecHandle, CurrentActorInfo, CurrentActivationInfo);
        EndAbility(CurrentSpecHandle, CurrentActorInfo, CurrentActivationInfo, true, false);
    }

    /** ★ 用 SetByCaller 写入本次抖动后的冷却秒数（§04 §7.4） */
    virtual void ApplyCooldown(const FGameplayAbilitySpecHandle Handle,
                               const FGameplayAbilityActorInfo* ActorInfo,
                               const FGameplayAbilityActivationInfo ActivationInfo) const override
    {
        const ABrotatoWeapon* W = Cast<ABrotatoWeapon>(GetCurrentSourceObject());
        const float NextCd = FWeaponFireCore::GetNextCooldownSeconds(
            W->RuntimeStats.CooldownSeconds, RunSubsystem->Weapons.Num(), W->NbShotsTaken);

        FGameplayEffectSpecHandle Spec = MakeOutgoingGameplayEffectSpec(CooldownGameplayEffectClass, 1.f);
        Spec.Data->SetSetByCallerMagnitude(BrotatoTags::Data_Cooldown, NextCd);
        Spec.Data->DynamicGrantedTags.AddTag(BrotatoTags::Cooldown_Weapon_Slot(W->SlotIndex));
        ApplyGameplayEffectSpecToOwner(Handle, ActorInfo, ActivationInfo, Spec);
    }
};
```

**授予方式**：玩家装备 N 把武器 → 授予 N 个 `FGameplayAbilitySpec`（同一个 Ability 类，`SourceObject` 各指向不同 `ABrotatoWeapon` 实例）。

### 9.3 ★ 冷却 = GAS 原生 Cooldown GE（v2.0 反转旧决议）

旧版以「帧精度 / 抖动 / 射击中暂停」为由拒绝 Cooldown GE。逐条给出原生解法：

| Brotato 需求 | ★ UE 原生解法 |
|---|---|
| 冷却硬下限（原作 2 帧） | 秒制常量 `MinWeaponCooldown = 1.f/30.f`；时间量不取整 |
| 每次射击 `±min(N×CD/5, N×0.0833s)` 随机抖动 | 重写 `ApplyCooldown()`，`SetByCaller` 写入本次秒数 —— 这正是 SetByCaller 的标准用途 |
| **射击过程中冷却不递减** | **攻击序列结束时才 Apply Cooldown GE**。原作「开火即设定 + 射击期间冻结」与此**数学等价**（总间隔 = 攻击时长 + 冷却） |
| 攻速变化时立即重算 / 压缩当前冷却 | `ASC->ModifyActiveGameplayEffectStartTime()` 修改剩余时长，或 Remove + 重新 Apply |
| 大装填（每 X 发 × 倍率） | 在 `GetNextCooldownSeconds()` 内判断，写入 Spec 即可 |

**收益**：
- UI 直接读 `GetCooldownTimeRemaining()` / `GetActiveGameplayEffectRemainingDuration()`，不再自维护倒计时；
- 冷却状态天然是 Tag（`Cooldown.Weapon.{Slot}`），Hook / 物品 / 调试面板都能查询与拦截；
- 暂停、时间缩放、存档读档（GE 重建）全部由 GAS 兜住；
- `CheckCooldown()` 与 `ActivationBlockedTags` 直接串联，无需在 `CanActivateAbility` 手写计数器判断。

**Tier C（炮塔 / 无 ASC 敌人）**：结构体内 `float CooldownRemaining -= DeltaTime`，公式仍调用 `FWeaponFireCore::GetNextCooldownSeconds()`，与 Tier A 共享同一份秒制实现。

### 9.4 `UAbilityTask_MeleeSwing`（挥击时序）

这是练 AbilityTask 的最佳素材。时序按**秒**推进，缓动用 `UCurveFloat` 资产（美术可视化可调）：

```cpp
UCLASS()
class UAbilityTask_MeleeSwing : public UAbilityTask
{
public:
    DECLARE_DYNAMIC_DELEGATE(FSwingEvent);
    UPROPERTY(BlueprintAssignable) FSwingEvent OnHitboxEnable;
    UPROPERTY(BlueprintAssignable) FSwingEvent OnHitboxDisable;
    UPROPERTY(BlueprintAssignable) FSwingEvent OnFinished;

    UAbilityTask_MeleeSwing() { bTickingTask = true; }   // ★ AbilityTask 原生 Tick

    virtual void Activate() override
    {
        // 计算三段时长（秒，§04 §8.1）
        const float AtkSpd = (StatSnapshot.AttackSpeed + Stats.AttackSpeedMod) / 100.f;
        const float RangeFactor = FMath::Max(0.f,
            Stats.MaxRange / FMath::Clamp(70.f * (1.f + AtkSpd / 3.f), 70.f, 120.f));
        AtkDuration  = FMath::Max(0.01f, 0.2f - AtkSpd / 10.f) + RangeFactor * 0.15f;
        BackDuration = AtkSpd > 0.f ? 0.2f / (1.f + AtkSpd * 3.f) : 0.2f;
        RecoilDuration = Stats.RecoilDuration;   // 已被攻速除算

        EnterPhase(EPhase::Recoil, RecoilDuration);
    }

    virtual void TickTask(float DeltaTime) override
    {
        PhaseElapsed += DeltaTime;
        if (PhaseElapsed < PhaseDuration) { UpdateSpriteTransform(PhaseElapsed / PhaseDuration); return; }
        const float Carry = PhaseElapsed - PhaseDuration;   // ★ 余量结转，避免长帧丢时序
        AdvancePhase();
        PhaseElapsed = Carry;
    }

private:
    enum class EPhase : uint8 { Recoil, SweepPrep, Forward, SweepFirstHalf, SweepSecondHalf, Return, Done };
    void EnterPhase(EPhase P, float DurationSeconds)
    { Phase = P; PhaseDuration = FMath::Max(KINDA_SMALL_NUMBER, DurationSeconds); PhaseElapsed = 0.f; }

    void AdvancePhase()
    {
        switch (Phase)
        {
        case EPhase::Recoil:
            // 音效在此播放（★ 早于 hitbox 开启，原作如此）
            AbilitySystemComponent->ExecuteGameplayCue(BrotatoTags::Cue_Weapon_MeleeSwing);
            OnHitboxEnable.ExecuteIfBound();
            EnterPhase(bSweep ? EPhase::SweepFirstHalf : EPhase::Forward,
                       bSweep ? AtkDuration / 4.f : AtkDuration / 2.f);
            break;
        // ... 其余阶段
        case EPhase::Return:
            if (Stats.bDealDmgOnReturn) OnHitboxDisable.ExecuteIfBound();
            Phase = EPhase::Done;
            OnFinished.ExecuteIfBound();
            EndTask();
            break;
        }
    }

    /** 缓动：优先用 UCurveFloat 资产；以下为对齐 Godot TRANS_EXPO/EASE_OUT 的默认实现 */
    UPROPERTY(EditDefaultsOnly) TObjectPtr<UCurveFloat> SwingEaseCurve;
    static float EaseExpoOut(float T) { return T >= 1.f ? 1.f : 1.f - FMath::Pow(2.f, -10.f * T); }
    static float EaseLinear (float T) { return T; }

    float PhaseElapsed = 0.f, PhaseDuration = 0.f;
};
```

> **★ 余量结转（Carry）** 是可变帧率下保持时序准确的关键：低帧时一次 Tick 可能跨过整个阶段，把超出部分带进下一阶段即可保证总时长准确。

### 9.5 近战命中去重


### 10.3 AI 方案选择：StateTree 而非行为树

| 方案 | 适用对象 | 理由 |
|---|---|---|
| ❌ 行为树（BehaviorTree + Blackboard） | 不用 | 144 个 BT 实例每帧遍历树 = 性能灾难；而敌人只有"1 移动行为 + 1 攻击行为"的固定组合 |
| ✅ **`StateTree`**（UE5 原生轻量状态机） | **Boss / 精英 / 结构物（≤ 10 个）** | 阶段递进、条件转移、可视化编辑 —— 正是 Boss 阶段机的标准答案，且比 BT 轻得多 |
| ✅ **数据驱动批处理**（`MovementBehaviorType` + `AttackBehaviorType` 枚举 + 按类型分桶） | **普通敌人（100–144）** | 与原作的两个 Behavior 节点 1:1 对应；无每实例状态机开销。后续可平移到 Mass Processor |

### 15.2 ★ 双路径一致性测试（最重要的新增测试）

```cpp
// Tests/GAS/DualPathConsistencyTest.cpp
// 目标：确保 GAS ExecCalc 与纯函数 Pipeline 结果完全一致
IMPLEMENT_SIMPLE_AUTOMATION_TEST(FDualPathTest, "Brotato.GAS.DualPathConsistency", ...)
bool FDualPathTest::RunTest(const FString&)
{
    for (int32 Seed = 0; Seed < 1000; ++Seed)
    for (const FDamageCase& C : GenerateCases())   // 覆盖 armor 正/负/0、crit、dodge、protection
    {
        // 路径 A：GAS
        FBrotatoRandom RngA; RngA.Seed(Seed);
        const int32 ResultA = RunThroughExecCalc(C, RngA);

        // 路径 B：纯函数
        FBrotatoRandom RngB; RngB.Seed(Seed);
        const int32 ResultB = RunThroughPipeline(C, RngB);

        TestEqual(FString::Printf(TEXT("Seed %d Case %s"), Seed, *C.ToString()), ResultA, ResultB);
    }
    return true;
}
```

## 18. ★ 原作 Bug / 怪异行为：照抄 or 修复（决策清单）

> 1:1 复刻不等于"把 bug 也一起抄"。凡影响**玩法平衡 / 手感**的怪异行为 → **照抄**；凡属**纯实现缺陷**（玩家感知不到，只会导致数据错乱）→ **修复**。
> 本清单是唯一权威来源。新发现的项**必须追加到此表**（对应 §10 §6 的维护约定）。

| # | 原作行为 | 类别 | 决策 | 理由 / UE 侧做法 | 出处 |
|---|---|---|---|---|---|
| 1 | `Effect.unapply()` 用 `Array.erase([key, value])` 值比较移除，同一物品叠多份时会**错删** | 实现缺陷 | ✅ **修复** | 改用 `FActiveGameplayEffectHandle` + `FGuid` 精确移除（§5.3） | §05 §2.1 |
| 2 | `StatCapEffect.unapply()` **硬复位 999999** 而非还原 `base_value` | 怪异但无害 | 📋 **照抄** | 仅用于 `hp_cap`/`speed_cap`（默认本就是 999999）；移除 GE 后 Aggregator 自动回落，行为一致。**不可用于 `dodge_cap`** | §03 §8.3、§05 §2.4 |
| 3 | 屏震偏移 `Vector2(randf(), randf())` —— **只向右下**，不对称 | 手感特征 | 📋 **照抄** | 这是原版"抖动感"的识别特征，改成对称随机会立刻被老玩家察觉 | §04 §10.1 |
| 4 | 屏震覆盖条件是 `强度>当前` **且** `时长>当前`，而所有时长都是 0.1 s → **一段震动内第一个触发者胜** | 怪异 | 📋 **照抄** | 实际效果是"屏震不叠加"，对高攻速 build 的观感至关重要 | §04 §10.1、§07 V03 |
| 5 | `repeating = -1` 表示**只触发一次**（因 `if repeating > 0` 才注册重复） | 数据语义 | 📋 **照抄** | 直接影响 20 波刷怪时间轴 | §06 §4.2 |
| 6 | 暴击用**原始伤害**重算而非"已减甲伤害 × 倍率" | 平衡核心 | 📋 **照抄** | 对减法护甲的敌人两种算法结果不同，影响全部 build 收益曲线 | §02 §5.2 |
| 7 | 幸运对 **Tier 抽取**用 `/(1+|L|)`，对**消耗品掉落**用线性 `(1+L)` —— 负幸运下两套公式 | 不一致 | 📋 **照抄** | 负幸运极少出现，但改动会影响 Lucky/Glutton 的数值预期 | §02 §4.11、§05 §4.9 |
| 8 | 升级资源里存在 4 组**未注册的废弃项**（`accuracy` / `crit_damage` / `damage` / `weapon_slot`），且 key 不在 `init_stats()` | 死代码 | ❌ **忽略** | 不导入 `DT_Upgrades`；Editor 校验器需能识别并告警 | §02 §6.5 |
| 9 | `stat_crit_damage` 键**不存在**于 `init_stats()`（玩家无暴击倍率属性，只能由武器提供） | 设计约束 | 📋 **照抄** | 不要"顺手"加一个 `CritDamage` Attribute，会破坏 Precise 系武器的独占性 | §02 §4.12 |
| 10 | 敌人 `009` 有完整实现但**未出现在 Zone 1 任何波表** | 未启用内容 | ⚙️ **实现但不配表** | 保留 `DT_Enemies` 行与行为实现（无尽额外组/Mod 可能用），但不进 20 波配表 | §06 §7.3 |
| 11 | `000_hordes/group_3b.tres` 存在但**未被 `horde_groups` 引用** | 未启用内容 | ⚙️ **导入但不启用** | 进 `DT_WaveGroups`，`bEnabled = false` | §06 §6.4 |
| 12 | `weapons/melee/cactus_mace/` 的 id 是 `weapon_cacti_club` —— **目录名 ≠ id** | 命名不一致 | 📋 **照抄 id** | 一切以 `weapon_id` / `my_id` 为准；导入脚本不得按目录名推断 id | §04 §1.4、§08 §6.2 |
| 13 | `weapons/melee/knuckles/` 的 `weapon_id = ""` | 特殊数据 | 📋 **照抄** | 空 `weapon_id` 作为"不进商店池"的标记 | §04 §1.4 |
| 14 | 角色 `tier` 字段在**运行时被 UI 改写**成"已通关最高危险度" | 字段复用 | ✅ **修复（拆字段）** | UE 侧拆成 `Tier`（只读数据）+ `DisplayDangerBeaten`（运行时），避免数据资产被污染 | §03 §8.3 |
| 15 | `hp_start_wave` 计算 `max(1, maxhp × pct/100)` —— 百分比为 0 时仍保底 1 HP | 保底 | 📋 **照抄** | 防止开波即死 | §02 §4.1 |
| 16 | Renegade 的 `DMG% = -400` 导致乘区 `-3` → 负伤害，靠 `max(1, ...)` 兜底 | 平衡设计 | 📋 **照抄** | **务必保留 `max(1,...)`，且中间值允许为负**（不要提前 clamp 到 0） | §03 §8.3 |
| 17 | 超上限剔除敌人时 `can_drop_loot = false`，但**计入 Pacifist 的波末收获** | 怪异 | 📋 **照抄** | 影响 Pacifist 的实际收益 | §06 §5.2 |
| 18 | `Utils.get_chance_success()` 在 `chance == 0` 时**直接 return false**（不掷骰） | 实现细节 | 📋 **照抄** | 会改变随机序列消耗次数 → 影响确定性回归 | §02 §10.2 |
| 19 | 闪避用 `randf() <`，暴击用 `randf() <=` | 不一致 | 📋 **照抄** | 概率差 1 个浮点 epsilon，但确定性回归要求严格一致 | §02 §4.4 |
| 20 | 弹射后 `weapon_stats.max_range = 99999` —— **直接改了共享的 stats 对象** | 实现缺陷 | ✅ **修复** | UE 侧 `FProjectileInstance` 持有自己的 `MaxRange` 副本，不回写武器 `RuntimeStats` | §04 §9.3 |
| 21 | 读档时若 Effect 实例重复反序列化，会导致 `unapply` 失效（原作用 `cache_effect_hashes` 缓解） | 实现缺陷 | ✅ **修复** | 每个 Effect 实例分配稳定 `FGuid` 并序列化（§5.3、§08 §5.3） | §05 §2.8 |
| 22 | 无尽模式 `wave_index < 10 → +10` —— **永远不复用第 1–10 波模板** | 设计意图 | 📋 **照抄** | 无尽只重复后半段高压波，是节奏设计不是 bug | §06 §3 |
